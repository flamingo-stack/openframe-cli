## Overview

This file implements AWS identity resolution and confirmation for EKS cluster operations. It ensures that before any billed AWS resource operation runs, the user's active credentials (via `--profile` or the default credential chain) are explicitly verified — either through interactive confirmation or clear non-interactive logging — to prevent accidental operations against the wrong AWS account.

## Key Components

- **`awsIdentity`** — struct mapping the JSON output of `aws sts get-caller-identity` (`Account`, `Arn`).
- **`awsConfigDocsURL`** — constant pointing to the official AWS CLI configuration guide, surfaced in error messages.
- **`describeAWSSelection(profile string) string`** — formats a human-readable description of the credential source (named profile or default credentials).
- **`confirmAWSIdentity(ctx, exec, profile) error`** — core function that:
  - Runs `aws sts get-caller-identity` to resolve the active identity.
  - Distinguishes "nothing configured" errors from "this profile is broken" errors, listing available profiles as alternatives.
  - Prompts interactively for confirmation (unless running non-interactively, in which case it logs the identity instead).
  - Returns an error with actionable hints if the user declines or authentication fails.
- **`confirmAWSIdentityFn` / `awsInteractiveFn`** — package-level function variables acting as test seams for interactive confirmation and TTY/CI detection, allowing hermetic unit tests.

## Usage Example

```go
package cluster

import (
	"context"

	"github.com/flamingo-stack/openframe-cli/internal/shared/executor"
)

func provisionEKSCluster(ctx context.Context, exec executor.CommandExecutor, profile string) error {
	// Verify AWS identity before any billed operation begins.
	if err := confirmAWSIdentity(ctx, exec, profile); err != nil {
		return err
	}

	// Proceed with EKS cluster creation/deletion using the confirmed identity.
	return nil
}
```

This is typically invoked at the start of any command that provisions or modifies EKS resources, guarding against accidental cross-account operations. Its GKE counterpart is `discovery.AuthFlow`.
