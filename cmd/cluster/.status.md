Provides the `cluster status` subcommand, resolving a cluster name and rendering its health, nodes, apps, and resource info in text, JSON, or YAML formats.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `getStatusCmd` | `func` | Builds and returns the `cobra.Command` for `cluster status`, wiring flags and pre-run validation |
| `runClusterStatus` | `func` | Core handler — resolves cluster name (interactive or explicit), validates `--output`, then dispatches to the appropriate renderer |
| `printClusterStatus` | `func` | Serialises a `models.ClusterInfo` value to stdout as indented JSON or YAML |

## Usage Example

```bash
# Interactive cluster picker (text output)
openframe cluster status

# Named cluster, detailed view
openframe cluster status my-cluster --detailed

# Machine-readable output (requires explicit name)
openframe cluster status my-cluster -o json
openframe cluster status my-cluster -o yaml
```

```go
// Internal wiring (how the command is registered)
statusCmd := getStatusCmd()
clusterCmd.AddCommand(statusCmd)
```

## Flags

| Flag | Default | Description |
|------|---------|-------------|
| `-o`, `--output` | `text` | Output format: `text`, `json`, or `yaml` |
| `--detailed` | `false` | Show extended node and resource detail (from global status flags) |
| `--no-apps` | `false` | Suppress installed-applications section |
| `--verbose` | `false` | Enable verbose logging |

## Notes

- Machine output (`json`/`yaml`) bypasses the interactive picker and **requires** an explicit cluster name argument; omitting it returns an error immediately.
- Both machine formats reuse the `json:` struct tags on `models.ClusterInfo`, ensuring consistent field names.
- Output format validation happens **before** any interactive prompt or list operation, preventing silent failures.
