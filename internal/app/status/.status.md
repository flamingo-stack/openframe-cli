# status.go

Aggregates OpenFrame platform status—cluster health, ArgoCD application sync/health, and admin access credentials—into a single `Report` used by the `openframe app status` and `openframe app access` commands.

## Key Components

- **`Lister`** — Interface for listing ArgoCD applications in the target cluster.
- **`PasswordReader`** — Interface for retrieving the initial ArgoCD admin password.
- **`HealthChecker`** — Interface for checking cluster reachability/readiness.
- **`Report`** — Struct holding aggregated status: cluster health, application list, sync/health counts, and admin password.
  - `Ready() bool` — Returns true only if the cluster is reachable and all applications are synced and healthy.
  - `Summary() string` — Produces a one-line human-readable status message (e.g., "3/3 synced, 3/3 healthy — READY").
- **`Service`** — Orchestrates status collection from injected `Lister`, `HealthChecker`, and `PasswordReader` dependencies.
  - `NewService(lister, health, password) *Service` — Constructor; `health` and `password` are optional (nil-safe), `lister` is required.
  - `Report(ctx, verbose) (Report, error)` — Gathers health, applications, and admin password. Health and password failures are non-fatal; only a failure to list applications returns a hard error.
- **`summarize(apps)`** — Internal helper counting total, synced, and healthy applications.

## Usage Example

```go
package main

import (
	"context"
	"fmt"

	"github.com/flamingo-stack/openframe-cli/internal/status"
)

func main() {
	ctx := context.Background()

	// lister, healthChecker, and passwordReader implement the
	// status.Lister, status.HealthChecker, and status.PasswordReader interfaces.
	svc := status.NewService(lister, healthChecker, passwordReader)

	rep, err := svc.Report(ctx, false)
	if err != nil {
		fmt.Println("failed to gather status:", err)
		return
	}

	fmt.Println(rep.Summary())
	if rep.Ready() {
		fmt.Println("Platform is fully operational")
	}
	if rep.AdminPassword != "" {
		fmt.Println("Admin password:", rep.AdminPassword)
	}
}
```

## Notes

- `Report.HealthErr` surfaces health-check failures without failing the whole report, allowing callers to render partial status (e.g., applications listed but node health unavailable).
- `Summary()` avoids contradicting renderers that already display a partial table with a health warning.
