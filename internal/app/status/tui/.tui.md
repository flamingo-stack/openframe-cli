# tui.go

Implements an interactive, k9s-style terminal UI for viewing and managing ArgoCD application status, backed by [Bubble Tea](https://github.com/charmbracelet/bubbletea). It powers the `app status --interactive` command, letting users navigate applications, view details, trigger syncs, and auto-refresh status without leaving the terminal.

## Key Components

- **`Syncer`** — function type `func(ctx, names []string) error` used to trigger ArgoCD syncs for selected apps.
- **`Run(ctx, svc, sync, verbose)`** — entry point that builds the `model` and starts the Bubble Tea program; treats context cancellation (Ctrl+C) as a clean exit.
- **`model`** — the Bubble Tea model holding UI state: loaded report, cursor position, detail/list view toggle, and status notes.
- **`model.Init/Update/View`** — standard Bubble Tea lifecycle methods:
  - `Init` kicks off the first refresh and a periodic tick (every `refreshEvery` = 3s).
  - `Update` handles `refreshMsg`, `syncDoneMsg`, `tickMsg`, and key events (`up/down`/`j/k` navigate, `enter` toggles detail, `s` syncs selected app, `r` refreshes, `q`/`esc`/`ctrl+c` quits).
  - `View` renders either the list view or the detail view, plus a footer with keybinding hints.
- **`listView(m)`** — renders a table of apps with name, sync status, and health, highlighting the selected row.
- **`detailView(app)`** — renders full detail for the selected `argocd.Application` (health, sync, namespace, repo, revision, operation state, conditions).
- **`colorByHealth(health, text)`** — colorizes text green/red/yellow based on ArgoCD health state.

## Usage Example

```go
package main

import (
	"context"

	appstatus "github.com/flamingo-stack/openframe-cli/internal/app/status"
	"github.com/flamingo-stack/openframe-cli/internal/tui"
)

func main() {
	ctx := context.Background()
	svc := appstatus.NewService(/* ... */)

	syncFn := func(ctx context.Context, names []string) error {
		// call ArgoCD client to sync the given app names
		return nil
	}

	if err := tui.Run(ctx, svc, syncFn, false); err != nil {
		panic(err)
	}
}
```

The UI blocks until the user quits (`q`), refreshing the status report every 3 seconds and reusing the same `appstatus.Service` read path as the non-interactive `app status` command.
