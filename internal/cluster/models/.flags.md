Defines flag structures and validation logic for cluster-related CLI commands (create, list, status, delete, cleanup). It builds on `flags.CommonFlags` for shared global flags and adds command-specific options, including cloud-provider-specific flags for EKS and GKE clusters.

## Key Components

- **`GlobalFlags`** - Type alias for `flags.CommonFlags`, the shared base for all cluster commands.
- **`CreateFlags`** - Flags for cluster creation, including local (`ClusterType`, `NodeCount`, `K8sVersion`) and cloud-only options (`Region`, `Profile`, `Project`, `MachineType`, `MinNodes`, `MaxNodes`, `Spot`, `HA`, `BackendConfig`).
- **`ListFlags`**, **`StatusFlags`**, **`DeleteFlags`**, **`CleanupFlags`** - Command-specific flag sets embedding `GlobalFlags`.
- **`AddGlobalFlags`, `AddCreateFlags`, `AddListFlags`, `AddStatusFlags`, `AddDeleteFlags`, `AddCleanupFlags`** - Register flags on a `cobra.Command`.
- **`ValidateClusterName`** - Enforces DNS-1123-style naming rules (alphanumeric/hyphen, 1-63 chars, must start/end alphanumeric).
- **`ValidateGlobalFlags`, `ValidateCreateFlags`, `ValidateListFlags`, `ValidateStatusFlags`, `ValidateDeleteFlags`, `ValidateCleanupFlags`** - Validate flag combinations, including cross-cloud conflict checks (for example, rejecting `--project` on EKS or `--ha` on non-GKE clusters) and node-count bounds.

## Usage Example

```go
cmd := &cobra.Command{
    Use: "create [name]",
    RunE: func(cmd *cobra.Command, args []string) error {
        if err := models.ValidateCreateFlags(createFlags); err != nil {
            return err
        }
        // proceed with cluster creation
        return nil
    },
}

createFlags := &models.CreateFlags{}
models.AddGlobalFlags(cmd, &createFlags.GlobalFlags)
models.AddCreateFlags(cmd, createFlags)

if err := models.ValidateClusterName("my-cluster"); err != nil {
    log.Fatal(err)
}
```

## Notes

- `ValidateCreateFlags` normalizes `--type` aliases (for example, `aws` → `eks`) via `ParseClusterType`, ensuring downstream code always sees canonical values.
- Cloud-specific flags are strictly rejected for non-cloud cluster types to avoid silent misconfiguration.
