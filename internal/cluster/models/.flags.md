# flags.go

Defines flag structs and validation logic for the cluster subcommands (`create`, `list`, `status`, `delete`, `cleanup`) of the OpenFrame CLI, including cluster name validation and cross-cloud flag consistency checks.

## Key Components

- **`GlobalFlags`** - Type alias for `flags.CommonFlags`, the shared base flag set embedded in all command-specific flag structs.
- **`CreateFlags`** - Flags for cluster creation, including cluster type, node count, Kubernetes version, and cloud-only options (region, profile, project, machine type, node scaling bounds, spot, HA, backend config).
- **`ListFlags`** - Flags for listing clusters (`Quiet`, `All` for external cloud discovery).
- **`StatusFlags`** - Flags for cluster status (`Detailed`, `NoApps`).
- **`DeleteFlags`** / **`CleanupFlags`** - Each carries a `Force` flag to skip confirmation prompts.
- **`AddGlobalFlags`, `AddCreateFlags`, `AddListFlags`, `AddStatusFlags`, `AddDeleteFlags`, `AddCleanupFlags`** - Register the respective flags on a `cobra.Command`.
- **`ValidateClusterName`** - Enforces DNS-1123-like naming rules (max 63 chars, alphanumeric/hyphen, must start/end alphanumeric).
- **`ValidateGlobalFlags`, `ValidateCreateFlags`, `ValidateListFlags`, `ValidateStatusFlags`, `ValidateDeleteFlags`, `ValidateCleanupFlags`** - Validate flag combinations, including cloud-specific requirements (e.g., `--region`/`--project` required for GKE with `--skip-wizard`) and mutual exclusivity between AWS/GCP-specific flags.

## Usage Example

```go
cmd := &cobra.Command{
    Use: "create [cluster-name]",
    RunE: func(cmd *cobra.Command, args []string) error {
        if err := models.ValidateClusterName(args[0]); err != nil {
            return err
        }
        if err := models.ValidateCreateFlags(createFlags); err != nil {
            return err
        }
        // proceed with cluster creation
        return nil
    },
}

createFlags := &models.CreateFlags{}
models.AddGlobalFlags(cmd, &createFlags.GlobalFlags)
models.AddCreateFlags(cmd, createFlags)
```

Validation rejects invalid combinations early, such as passing `--project` with `--type eks`, or omitting `--region` for `--type gke` when `--skip-wizard` is set, ensuring cloud provisioning intent is unambiguous before execution.
