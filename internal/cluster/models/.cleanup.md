Defines the `CleanupResult` model used to track the outcome of a best-effort cluster cleanup operation, capturing what was actually removed and which phases failed, so summaries reflect real results rather than assuming full success.

## Key Components

- **`CleanupResult`** — struct holding `NodesPruned` (count of removed objects) and `Failures` (human-readable list of per-phase failure messages).
- **`AddFailure(phase string, err error)`** — appends a formatted failure message (`"<phase>: <err>"`) to `Failures`.
- **`Removed() int`** — returns the total number of objects successfully cleaned up.
- **`Partial() bool`** — returns `true` if any phase failed, indicating the cleanup completed but left some resources behind.

## Usage Example

```go
result := &models.CleanupResult{}

if err := pruneDockerImages(); err != nil {
    result.AddFailure("docker image prune", err)
} else {
    result.NodesPruned++
}

if err := pruneUnusedVolumes(); err != nil {
    result.AddFailure("volume prune", err)
} else {
    result.NodesPruned++
}

if result.Partial() {
    fmt.Printf("Cleanup completed with issues (%d removed):\n", result.Removed())
    for _, f := range result.Failures {
        fmt.Println(" -", f)
    }
} else {
    fmt.Printf("Cleanup successful: %d objects removed\n", result.Removed())
}
```

This pattern ensures each cleanup phase is isolated—failures don't halt the process—while still giving users an accurate, honest report of what succeeded and what didn't.
