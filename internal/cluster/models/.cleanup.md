Represents the outcome of a best-effort cluster cleanup run, tracking what was actually removed and which phases failed, so summaries can report real results instead of a hardcoded success message.

## Key Components

- **`CleanupResult`** - Struct that accumulates cleanup outcomes:
  - `NodesPruned` - count of nodes/objects successfully removed
  - `Failures` - slice of human-readable failure messages, one per failed phase
- **`AddFailure(phase string, err error)`** - Records a phase failure, formatting it as `"phase: error"` and appending to `Failures`
- **`Removed() int`** - Returns the total count of objects removed (currently `NodesPruned`)
- **`Partial() bool`** - Returns `true` if any phase failed, indicating the cleanup completed but left some resources behind

## Usage Example

```go
package main

import (
	"errors"
	"fmt"
)

func runCleanup() models.CleanupResult {
	result := models.CleanupResult{}

	// Phase 1: prune nodes (best-effort)
	pruned, err := pruneNodes()
	if err != nil {
		result.AddFailure("prune-nodes", err)
	} else {
		result.NodesPruned = pruned
	}

	// Phase 2: remove unused images (best-effort)
	if err := removeUnusedImages(); err != nil {
		result.AddFailure("remove-images", errors.New("docker daemon unreachable"))
	}

	return result
}

func main() {
	result := runCleanup()

	fmt.Printf("Removed %d objects\n", result.Removed())

	if result.Partial() {
		fmt.Println("Cleanup completed with issues:")
		for _, f := range result.Failures {
			fmt.Printf("  - %s\n", f)
		}
	} else {
		fmt.Println("Cleanup completed successfully")
	}
}
```

This design ensures cleanup commands never mask failures behind a generic success message, giving users an honest, actionable summary of partial cleanups.
