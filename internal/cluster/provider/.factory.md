## factory.go

Implements a factory function for constructing cluster `Provider` instances based on cluster type, abstracting the creation logic for k3d, EKS, and GKE providers.

## Key Components

- **`New(clusterType models.ClusterType, exec executor.CommandExecutor) (Provider, error)`** — Factory function that returns the appropriate `Provider` implementation:
  - `models.ClusterTypeK3d` or empty string → k3d provider (default for local development)
  - `models.ClusterTypeEKS` → AWS EKS provider, with verbose terraform output tied to `pterm.PrintDebugMessages`
  - `models.ClusterTypeGKE` → Google GKE provider, same verbose behavior
  - Any unrecognized type → returns a `models.NewInvalidConfigError`

## Usage Example

```go
package main

import (
	"log"

	"github.com/flamingo-stack/openframe-cli/internal/cluster/models"
	"github.com/flamingo-stack/openframe-cli/internal/cluster/providers/provider"
	"github.com/flamingo-stack/openframe-cli/internal/shared/executor"
)

func main() {
	exec := executor.NewCommandExecutor()

	p, err := provider.New(models.ClusterTypeK3d, exec)
	if err != nil {
		log.Fatalf("failed to create provider: %v", err)
	}

	// Use the provider to manage cluster lifecycle
	_ = p
}
```

### Notes

- Passing an empty `models.ClusterType` defaults to the k3d provider, making it convenient for local development workflows where cluster type is optional.
- The `--verbose` CLI flag controls `pterm.PrintDebugMessages`, which determines whether EKS/GKE providers stream raw terraform output during apply operations.
- Unknown cluster types produce a structured configuration error rather than a panic, allowing callers to handle invalid input gracefully.
