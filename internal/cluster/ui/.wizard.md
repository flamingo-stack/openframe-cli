## Overview

`wizard.go` implements an interactive terminal wizard for configuring Kubernetes cluster creation in the OpenFrame CLI. It supports both k3d (local) and cloud-based (EKS/GKE) cluster types, guiding users through name, type, region/project, machine type, node count, and Kubernetes version selection before confirming the final configuration.

## Key Components

- **`ClusterConfig`** — Intermediate struct holding wizard answers (name, type, node count, K8s version, and cloud-specific fields like region, project, profile, machine type).
- **`(ClusterConfig) ToDomain()`** — Converts wizard answers into the domain `models.ClusterConfig`, attaching a `CloudConfig` block only for EKS/GKE cluster types.
- **`ConfigWizard`** — Orchestrates the step-by-step interactive prompts.
  - `NewConfigWizard()` — Creates a wizard with sensible defaults (k3d, 3 nodes, latest version).
  - `SetDefaults(...)` — Overrides default values (e.g., when a cluster name is pre-supplied).
  - `Run()` — Executes all wizard steps sequentially (name → type → cloud-specific prompts → node count → K8s version → confirmation), recursing on user rejection of the final summary.
- **`ConfigurationHandler`** — Higher-level entry point choosing between "quick" (defaults) and "wizard" (interactive) configuration flows.
  - `GetClusterConfig(clusterName string)` — Main entry point; prompts for creation mode and delegates accordingly.
  - `getQuickConfig(...)` — Returns a default k3d configuration.
  - `getWizardConfig(...)` — Runs `ConfigWizard` and converts the result to the domain model.

## Usage Example

```go
package main

import (
	"fmt"

	"github.com/flamingo-stack/openframe-cli/internal/cluster/ui"
)

func main() {
	handler := ui.NewConfigurationHandler()

	config, err := handler.GetClusterConfig("my-cluster")
	if err != nil {
		fmt.Println("Configuration failed:", err)
		return
	}

	fmt.Printf("Cluster configured: %+v\n", config)
}
```

This flow first presents a "Default configuration" vs "Interactive configuration" choice; selecting the latter walks the user through `ConfigWizard.Run()`, ultimately producing a fully populated `models.ClusterConfig` ready for cluster provisioning.
