Orchestrates checking, installing, and starting prerequisite tools (Docker, k3d, helm, etc.) required by the CLI, supporting both interactive and non-interactive (CI) modes.

## Key Components

- **`Installer`** — struct wrapping a `PrerequisiteChecker`; drives the check → install → verify → start flow.
- **`NewInstaller()`** — creates an `Installer` with the default prerequisite checker.
- **`NewInstallerWithChecker(checker *PrerequisiteChecker)`** — creates an `Installer` for a specific requirement set (e.g., k3d local vs. EKS cloud).
- **`(*Installer) CheckAndInstallNonInteractive(nonInteractive bool) error`** — main entry point. Checks all prerequisites, installs missing tools (auto-confirmed in non-interactive mode or via user prompt), and ensures Docker is running, starting it and waiting for readiness if needed.
- **`(*Installer) installSpecificTools(tools []string) error`** — installs a list of tools sequentially with spinner feedback, then verifies each was actually installed.
- **`(*Installer) installTool(tool string) error`** — looks up and runs the `Install` function for a single requirement by name.
- **`(*Installer) requirement(name string) *Requirement`** — case-insensitive lookup of a requirement by name.
- **`(*Installer) showManualInstructions()`** — prints a table of manual installation instructions when the user declines auto-install.
- **`(*Installer) showDockerStartInstructions()`** — prints OS-specific instructions (macOS/Linux/Windows) for manually starting Docker.
- **`containsTool(tools []string, name string) bool`** — helper checking case-insensitive membership in a tool list.

## Usage Example

```go
package main

import (
	"log"

	"github.com/flamingo-stack/openframe-cli/internal/cluster/prerequisites"
)

func main() {
	installer := prerequisites.NewInstaller()

	// nonInteractive=true auto-approves installs and Docker startup (e.g. in CI)
	if err := installer.CheckAndInstallNonInteractive(false); err != nil {
		log.Fatalf("prerequisite check failed: %v", err)
	}
}
```

Failures during install or Docker startup are returned immediately (fail-fast) rather than allowing execution to continue with an incomplete environment, since later cluster operations would fail anyway with a less clear error.
