## installer.go

Implements the `Installer` type, which orchestrates checking, installing, and starting the tools required by the CLI (e.g., Docker, k3d, helm) based on a data-driven set of `Requirement`s from a `PrerequisiteChecker`. It supports both interactive (prompt-based) and non-interactive (auto-approve) workflows, and provides platform-specific manual instructions when automated installation isn't possible or declined.

## Key Components

- **`Installer`** — Wraps a `*PrerequisiteChecker` and drives the check/install/start flow.
- **`NewInstaller()`** — Creates an `Installer` using the default prerequisite checker.
- **`NewInstallerWithChecker(checker *PrerequisiteChecker)`** — Creates an `Installer` bound to a custom requirement set (e.g., local k3d vs. cloud EKS prerequisites).
- **`CheckAndInstallNonInteractive(nonInteractive bool)`** — Main entry point: checks all requirements, installs missing tools (auto-confirmed if `nonInteractive` is true, otherwise prompts the user), and ensures Docker is running (starting it automatically or prompting as needed). Fails fast on any error rather than deferring failure to later cluster operations.
- **`installSpecificTools(tools []string)`** — Installs a list of tools sequentially with spinner-based progress feedback, then verifies each was actually installed.
- **`installTool(tool string)`** — Looks up and invokes the `Install` function for a single named requirement.
- **`showManualInstructions()`** — Renders a table of manual installation instructions for all requirements.
- **`showDockerStartInstructions()`** — Prints OS-specific (`darwin`/`linux`/`windows`) instructions for starting Docker manually.

## Usage Example

```go
package main

import (
	"log"

	"github.com/flamingo-stack/openframe-cli/internal/cluster/prerequisites"
)

func main() {
	// Use default prerequisites (Docker, k3d, helm, etc.)
	installer := prerequisites.NewInstaller()

	// Interactive mode: prompts the user before installing/starting tools
	if err := installer.CheckAndInstallNonInteractive(false); err != nil {
		log.Fatalf("prerequisite check failed: %v", err)
	}

	// Non-interactive mode: auto-installs and auto-starts Docker (e.g., in CI)
	if err := installer.CheckAndInstallNonInteractive(true); err != nil {
		log.Fatalf("prerequisite check failed: %v", err)
	}
}
```

Custom checker (e.g., cloud EKS prerequisites) can be supplied via `NewInstallerWithChecker`, allowing different tool sets to be validated depending on the target cluster type (local `k3d` vs. cloud).
