# ports.go

Implements dynamic port allocation for k3d clusters, ensuring the API, HTTP, and HTTPS ports selected don't conflict with existing k3d clusters or other services running on the host.

## Key Components

- **`PortConfig`** — Struct holding the allocated `API`, `HTTP`, and `HTTPS` port numbers for a cluster.
- **`(*K3dManager).findAvailablePorts`** — Determines an available `PortConfig` by first checking ports used by existing k3d clusters, then probing for actual TCP availability. Prefers standard ports (6550, 80, 443) and falls back to alternates (6551, 8080, 8443) or a scanned range.
- **`(*K3dManager).findPort`** — Helper that tries a list of preferred ports before scanning sequentially from a given start value (up to 1000 ports) for one that's both unused by k3d and TCP-available.
- **`(*K3dManager).getUsedPortsByExistingClusters`** — Runs `k3d cluster list --output json` (30s timeout) and parses node runtime labels and port mappings to build a set of ports already claimed by existing clusters. Returns an empty map on any error, falling back to live port checks.
- **`(*K3dManager).isPortAvailable`** — Checks TCP port availability by attempting a short-timeout dial to `127.0.0.1`; a refused/failed connection indicates the port is free. This avoids requiring elevated privileges for low-numbered ports.

## Usage Example

```go
func (m *K3dManager) createCluster(ctx context.Context, name string) error {
    ports, err := m.findAvailablePorts(ctx)
    if err != nil {
        return fmt.Errorf("failed to allocate ports: %w", err)
    }

    fmt.Printf("Allocated ports - API: %d, HTTP: %d, HTTPS: %d\n",
        ports.API, ports.HTTP, ports.HTTPS)

    // Use ports.API, ports.HTTP, ports.HTTPS when building
    // the k3d cluster create command arguments.
    return nil
}
```

## Notes

- Port scanning uses a bounded search window (1000 ports) starting from each fallback base to avoid unbounded loops.
- Errors from the `k3d` CLI or JSON parsing are treated as non-fatal; the function silently relies on live TCP checks instead.
- The `k3dClusterInfo` type (referenced but not defined here) is expected to model the JSON output of `k3d cluster list`, including nodes, roles, runtime labels, and port mappings.
