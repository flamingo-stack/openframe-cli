## ports.go

This file implements automatic TCP port allocation for k3d clusters, selecting available ports for the Kubernetes API, HTTP, and HTTPS endpoints while avoiding conflicts with existing clusters and other running services.

## Key Components

- **`PortConfig`** - Struct holding the three allocated ports: `API`, `HTTP`, and `HTTPS`.
- **`(*K3dManager) findAvailablePorts(ctx)`** - Main entry point that resolves a full `PortConfig`, preferring standard ports (6550, 80, 443) and falling back to alternates (6551, 8080, 8443) or a scanned range if those are taken.
- **`(*K3dManager) findPort(preferred, searchStart, usedPorts)`** - Tries a list of preferred ports first, then scans up to 1000 ports starting from `searchStart` for an available one.
- **`(*K3dManager) getUsedPortsByExistingClusters(ctx)`** - Runs `k3d cluster list --output json` (with a 30-second timeout) to inspect existing clusters and collect ports already reserved by their server/loadbalancer nodes.
- **`(*K3dManager) isPortAvailable(port)`** - Checks port availability via a TCP dial attempt on `127.0.0.1`, which works without elevated privileges even for ports below 1024.

## Usage Example

```go
manager := &K3dManager{
    executor: executor.NewCommandExecutor(),
}

ctx := context.Background()
ports, err := manager.findAvailablePorts(ctx)
if err != nil {
    log.Fatalf("port allocation failed: %v", err)
}

fmt.Printf("API port: %d, HTTP port: %d, HTTPS port: %d\n",
    ports.API, ports.HTTP, ports.HTTPS)
```

This is typically called internally during cluster creation, before invoking `k3d cluster create`, to inject dynamically resolved port mappings into the cluster configuration and avoid collisions with other local k3d clusters or services.
