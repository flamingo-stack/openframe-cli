## verify.go

This file implements Kubernetes cluster reachability verification for k3d clusters, using the native Go Kubernetes client instead of relying on the external `kubectl` binary. It handles kubeconfig context switching, TLS bypass for local clusters, TCP port readiness checks, and polling for node readiness before declaring a cluster usable.

## Key Components

- **`verifyClusterReachable(ctx, clusterName) (*rest.Config, error)`** — Core verification method on `K3dManager`. Loads the kubeconfig, switches to the `k3d-<clusterName>` context, applies insecure TLS settings for local development, waits for the API server's TCP port to open, then polls the Kubernetes API until at least one node reports `Ready`.
- **`isTemporaryError(err) bool`** — Determines whether an API error (e.g., connection refused, timeout, service unavailable) is transient and worth retrying.
- **`waitForTCPPort(ctx, host, port, maxRetries, retryDelay) error`** — Polls a TCP address until it accepts connections, avoiding premature API calls to a not-yet-listening port (important for Windows/WSL2 timing issues).
- **`extractHostPort(urlStr) (string, string, error)`** — Parses host and port from a REST config URL.
- **`getKubeconfigPath() string`** — Resolves the kubeconfig file path, respecting the `$KUBECONFIG` environment variable or defaulting to `~/.kube/config`.
- **`firstKubeconfigPath(kubeconfig string) string`** — Reduces a colon-separated `$KUBECONFIG` path list to a single usable file path, preferring the first existing file (mirrors `kubectl` precedence).
- **`cleanupStaleLockFiles(ctx) error`** — Removes stale kubeconfig lock files (`~/.kube/config.lock*`) that can block context switching.

## Usage Example

```go
manager := &K3dManager{verbose: true, executor: executor}

restConfig, err := manager.verifyClusterReachable(ctx, "my-cluster")
if err != nil {
    log.Fatalf("cluster not reachable: %v", err)
}

client, err := kubernetes.NewForConfig(restConfig)
if err != nil {
    log.Fatalf("failed to create client: %v", err)
}
```

This is typically invoked after cluster creation (e.g., in a `CreateCluster` workflow) to confirm the k3d cluster's API server is reachable and at least one node is ready before proceeding with further provisioning steps.
