Provides WSL/Linux-compatible kubeconfig directory management and k3d cluster data structures for the K3dManager, handling directory creation and file permission fixes within a WSL/Linux execution context.

## Key Components

### Types

| Type | Description |
|------|-------------|
| `k3dClusterInfo` | JSON-deserializable struct for `k3d cluster list` output, including server/agent counts and nodes |
| `k3dNode` | Represents a cluster node with role, creation time, labels, and port mappings |
| `PortMapping` | Host IP and port binding for a k3d node |

### Methods

| Method | Description |
|--------|-------------|
| `prepareKubeconfigDirectory` | Creates `~/.kube` with `755` permissions via bash; no-op on Windows (handled by WSL launcher) |
| `fixKubeconfigPermissions` | Sets `~/.kube/config` to `600` permissions; corrects root-owned files created by `sudo`-based k3d runs |

## Usage Example

```go
manager := &K3dManager{executor: myExecutor, verbose: true}

// Ensure ~/.kube exists before writing kubeconfig
if err := manager.prepareKubeconfigDirectory(ctx); err != nil {
    log.Fatal(err)
}

// Fix permissions after k3d writes config as root
if err := manager.fixKubeconfigPermissions(ctx); err != nil {
    log.Fatal(err)
}
```

## Notes

- Both methods delegate to `m.executor.Execute` using `bash -c`, making them Linux/macOS-only by design
- Windows support is intentionally omitted — the CLI is forwarded into WSL via the `wsllauncher`, where it runs as Linux
- `fixKubeconfigPermissions` uses `|| true` to avoid errors when `~/.kube/config` does not yet exist
