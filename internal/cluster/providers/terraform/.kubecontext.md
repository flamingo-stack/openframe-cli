Provides helpers for checking whether a context exists in the user's local kubeconfig, used to accurately determine cluster availability rather than assuming a context exists based on cluster name alone.

## Key Components

- **`KubeconfigHasContext(name string) bool`** — Reports whether the kubeconfig (loaded via `$KUBECONFIG` or `~/.kube/config` default rules) contains a context with the exact given name.
- **`KubeconfigContextMatching(match func(name string) bool) string`** — Loads the kubeconfig, sorts context names for deterministic ordering, and returns the first context name accepted by the `match` predicate, or an empty string if none match (or the kubeconfig cannot be loaded).

## Usage Example

```go
package main

import (
	"fmt"
	"strings"

	"your-module/terraform"
)

func main() {
	// Exact match check
	if terraform.KubeconfigHasContext("my-cluster") {
		fmt.Println("context exists")
	}

	// Pattern match, e.g. for a gcloud-style GKE context name
	ctx := terraform.KubeconfigContextMatching(func(name string) bool {
		return strings.HasPrefix(name, "gke_") && strings.Contains(name, "my-cluster")
	})
	if ctx != "" {
		fmt.Printf("found matching context: %s\n", ctx)
	} else {
		fmt.Println("no matching context found")
	}
}
```

**Note:** The cluster list's CONTEXT column must always be derived from these functions rather than fabricated from the cluster name, since a kubeconfig entry is only merged after a successful `apply` — a failed or pending workspace has no corresponding context.
