Provides helpers for checking whether the local kubeconfig file actually contains a given context, used to derive accurate cluster status instead of assuming a context exists based on naming conventions.

## Key Components

- **`KubeconfigHasContext(name string) bool`** — Reports whether the user's kubeconfig (loaded via `$KUBECONFIG` or `~/.kube/config` default rules) contains a context with the exact given name. Returns `false` on any load error, treating errors as "no context" rather than guessing.
- **`KubeconfigContextMatching(match func(name string) bool) string`** — Loads the kubeconfig and returns the first context name (sorted alphabetically for determinism) for which `match` returns `true`. Returns `""` if no context matches or the config can't be loaded. This allows callers to match provider-specific naming conventions, such as AWS EKS ARN-style contexts or GCP's `gke_<project>_<location>_<name>` format.

## Usage Example

```go
package main

import (
	"fmt"

	"yourmodule/terraform"
)

func main() {
	// Exact match check
	if terraform.KubeconfigHasContext("my-cluster") {
		fmt.Println("context found")
	}

	// Custom matching, e.g. GKE-style context names
	ctx := terraform.KubeconfigContextMatching(func(name string) bool {
		return len(name) > 4 && name[:4] == "gke_"
	})
	if ctx != "" {
		fmt.Printf("found GKE context: %s\n", ctx)
	}
}
```

**Design note:** The cluster list's CONTEXT column must always be derived from these functions rather than fabricated from a cluster name, since a context is only merged into the kubeconfig after a successful `apply` — a workspace whose plan or apply failed has no corresponding kubeconfig entry.
