## progress.go

Parses Terraform's `-json` machine-readable output stream and prints concise, human-friendly progress lines during long-running `apply` operations using `pterm`.

Terraform's `-json` mode emits one JSON object per line describing plan/apply events. This file filters that stream down to the meaningful lines (plan details, apply start/complete/errored, change summaries, and error diagnostics) and renders them incrementally as an `io.Writer`, so users see per-resource progress instead of a wall of raw JSON.

## Key Components

- **`applyEvent`** — struct capturing the subset of Terraform's JSON-UI schema needed for display (`@level`, `@message`, `type`).
- **`progressLine(line []byte, verbose bool) (string, bool)`** — converts a single JSON event line into a displayable message. Returns `ok=false` for noise (unparseable lines, refresh ticks, non-actionable events). In verbose mode, forwards every non-empty message; otherwise filters to `planned_change`, `apply_start`, `apply_complete`, `apply_errored`, `change_summary`, and error-level `diagnostic` events.
- **`progressWriter`** — an `io.Writer` implementation that buffers partial writes, splits input into complete lines, and prints each parsed event via `pterm.DefaultBasicText`.
- **`newProgressWriter(verbose bool) io.Writer`** — constructor returning a ready-to-use writer for wiring into a command's stdout/stderr pipe.

## Usage Example

```go
package main

import (
	"os/exec"
)

func runTerraformApply(verbose bool) error {
	cmd := exec.Command("terraform", "apply", "-json", "-auto-approve")
	cmd.Stdout = newProgressWriter(verbose)
	cmd.Stderr = newProgressWriter(verbose)
	return cmd.Run()
}
```

As Terraform streams JSON lines to stdout, `progressWriter.Write` accumulates bytes, extracts complete lines, and prints only the relevant progress messages (e.g., `Plan to create...`, `Apply complete!`), respecting `--silent`/verbosity settings via `pterm`.
