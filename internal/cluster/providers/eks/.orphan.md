## orphan.go

Detects and reports orphaned AWS resources created by an interrupted Terraform apply (e.g., after a `SIGINT`) that leave the cloud resource created but untracked in Terraform state. This is the EKS-specific counterpart to the GKE handler that detects HTTP 409/`alreadyExists` errors.

## Key Components

- **`awsResourceArnRE`** — Compiled regex that extracts an AWS ARN (`arn:aws...`) from a Terraform error message, used to name the orphaned resource concretely when possible.
- **`orphanFromInterruptedCreate(err error, terraformDir string) (string, bool)`** — Inspects an error message for signatures of an AWS "already exists" failure (`ResourceInUseException` or `AlreadyExists`). If found, returns a formatted remediation message (with the ARN, if extractable) explaining that the resource exists in AWS but is invisible to Terraform state, along with two resolution paths: delete the orphan in AWS, or `terraform import` it into state. Returns `false` for the boolean when the error doesn't match this pattern, signaling the caller to fall back to generic error handling.

## Usage Example

```go
_, err := runTerraformCreate(terraformDir)
if err != nil {
    if hint, ok := orphanFromInterruptedCreate(err, terraformDir); ok {
        // Replace the generic "re-run to resume" guidance, which would
        // loop forever in this case, with actionable remediation steps.
        return fmt.Errorf("cluster create failed: %s", hint)
    }
    return fmt.Errorf("cluster create failed: %w", err)
}
```

This function is intended to be called from the EKS cluster creation error-handling path, right after a failed `terraform apply`, to give users a clear, actionable message instead of a generic retry suggestion when the failure is caused by an interrupted create leaving a state-invisible AWS resource behind.
