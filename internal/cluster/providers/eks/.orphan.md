## Overview

`orphan.go` implements detection logic for a specific EKS cluster creation failure mode: orphaned AWS resources left behind when a `terraform apply` is interrupted (e.g., via `SIGINT`) after AWS has created a resource but before Terraform persists it to state. It inspects Terraform error output to identify this scenario and produces actionable remediation guidance instead of a generic retry hint.

## Key Components

- **`awsResourceArnRE`** — Compiled regex that extracts an AWS ARN from an error message, used to name the offending resource concretely when possible.
- **`orphanFromInterruptedCreate(err error, terraformDir string) (string, bool)`** — Inspects an error for `ResourceInUseException` or `AlreadyExists` signatures (case-insensitive). If matched, it returns a formatted remediation message (offering deletion or `terraform import` as fixes) and `true`. Otherwise returns an empty string and `false`, signaling the caller to fall back to default error handling.

## Usage Example

```go
package main

import (
	"errors"
	"fmt"
)

func main() {
	err := errors.New(`Error: creating EKS Cluster: ResourceInUseException: cluster already exists: arn:aws:eks:us-east-1:123456789012:cluster/my-cluster`)

	if msg, isOrphan := orphanFromInterruptedCreate(err, "/infra/eks/my-cluster"); isOrphan {
		fmt.Println(msg)
		// Prints remediation steps referencing the ARN and terraform import command
	} else {
		fmt.Println("re-run create to resume")
	}
}
```

This function is typically called from the cluster creation error path in the EKS package, allowing callers to surface specific, actionable guidance when a resume loop would otherwise be futile due to an untracked AWS resource collision.
