## orphan.go

Detects a specific AWS EKS failure mode where a Terraform `create` operation is interrupted (e.g., via SIGINT) after a cloud resource has been provisioned but before Terraform persists it to state. This leaves an "orphan" resource in AWS that is invisible to Terraform state, causing subsequent create attempts to collide with it (`ResourceInUseException` / `AlreadyExists`) and preventing `cluster delete` from cleaning it up, since delete only operates on state-tracked resources.

## Key Components

- **`awsResourceArnRE`** — Compiled regexp used to extract an AWS ARN from a Terraform error message, allowing the orphaned resource to be identified by name in remediation output.
- **`orphanFromInterruptedCreate(err error, terraformDir string) (string, bool)`** — Inspects an error message for signatures of this orphan scenario (`resourceinuseexception` or `alreadyexists`, case-insensitive). Returns:
  - `("", false)` if the error doesn't match this pattern.
  - A human-readable remediation message and `true` if it does, replacing the generic "re-run to resume" guidance (which would loop forever in this case) with actionable steps: delete the orphan in AWS, or import it into Terraform state via `terraform -chdir=<dir> import`.

## Usage Example

```go
if err := runTerraformApply(); err != nil {
    if msg, isOrphan := orphanFromInterruptedCreate(err, terraformDir); isOrphan {
        // Surface the specific remediation instead of a generic retry hint
        fmt.Println(msg)
        return
    }
    // Fall back to generic error handling / resume hint
    fmt.Println("terraform apply failed:", err)
}
```

This is typically called from the EKS cluster creation error-handling path, right after a Terraform `apply` fails, to give users precise, actionable steps instead of a misleading "just re-run" suggestion.
