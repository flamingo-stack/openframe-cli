Defines a structural error wrapper for the EKS package that attaches a "resume hint" to an error, ensuring the hint survives the generic Ctrl+C interruption handler which otherwise discards the error's message text.

## Key Components

- **`resumeHintError`** — struct wrapping an underlying `error` and a `hint` string. Implements the standard `Error()` and `Unwrap()` methods for error chain compatibility, plus a `ResumeHint()` method used by `internal/shared/errors` to extract the hint even when the operation was interrupted.
- **`withResumeHint(err error, hint string) error`** — constructor function that wraps an error with a resume hint, returning it as a plain `error` interface backed by `*resumeHintError`.

This file mirrors the equivalent implementation for GKE in `gke/resumehint.go`, keeping resume-hint behavior consistent across cloud providers.

## Usage Example

```go
func setupCluster() error {
	if err := createEKSCluster(); err != nil {
		return withResumeHint(err, "Run 'openframe eks resume' to continue setup")
	}
	return nil
}

// Later, when handling the error (e.g., after Ctrl+C or failure):
func handleError(err error) {
	type resumeHinter interface {
		ResumeHint() string
	}
	if rh, ok := err.(resumeHinter); ok {
		fmt.Println("Hint:", rh.ResumeHint())
	}
}
```

Because `ResumeHint()` is attached structurally rather than embedded in `Error()`'s message text, the interruption handler can still retrieve and display the hint even though it ignores `err.Error()` on Ctrl+C.
