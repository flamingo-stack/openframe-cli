Defines a structural mechanism for attaching a "resume hint" to errors in the EKS provisioning flow, ensuring the hint survives generic interruption handling (e.g., Ctrl+C) that would otherwise discard the error's message text.

## Key Components

- **`resumeHintError`** – A wrapper error type that pairs an underlying `error` with a `hint` string. Implements:
  - `Error() string` – delegates to the wrapped error's message.
  - `Unwrap() error` – enables `errors.Is`/`errors.As` chaining to the wrapped error.
  - `ResumeHint() string` – exposes the hint independently of `Error()`, so consumers (like `internal/shared/errors`) can retrieve it even when the interruption handler only prints "Operation cancelled by user." and ignores `err.Error()`.

- **`withResumeHint(err error, hint string) error`** – Constructor function that wraps a given error with a resume hint, returning it as a plain `error` interface backed by `*resumeHintError`.

This file is the EKS-specific counterpart to `gke/resumehint.go`, which provides identical behavior for GKE flows.

## Usage Example

```go
package eks

import "fmt"

func provisionCluster() error {
	if err := createControlPlane(); err != nil {
		return withResumeHint(err, "re-run with --resume to continue from control plane setup")
	}
	return nil
}

func handleError(err error) {
	fmt.Println("Operation cancelled by user.")

	type resumeHinter interface {
		ResumeHint() string
	}
	if rh, ok := err.(resumeHinter); ok {
		fmt.Println("Hint:", rh.ResumeHint())
	}
}
```

In this example, even though the interruption handler discards `err.Error()`, it can still recover the actionable resume hint by checking for the `ResumeHint()` method via a type assertion.
