Provides a mechanism to attach a "resume hint" to an error so that instructions on how to resume an interrupted operation survive the generic Ctrl+C interruption handler, which normally discards the error's message text.

## Key Components

- **`resumeHintError`** - An error wrapper struct that pairs an underlying `error` with a `hint` string. Implements `Error()`, `Unwrap()`, and `ResumeHint()` methods, allowing consumers (e.g., `internal/shared/errors`) to retrieve the hint even when the error message itself is discarded.
- **`withResumeHint(err error, hint string) error`** - Wraps a given error with a resume hint, returning a `*resumeHintError` that structurally carries the hint alongside the original error.

This is the EKS-specific counterpart to the GKE implementation found in `gke/resumehint.go`.

## Usage Example

```go
package eks

import "errors"

func provisionCluster() error {
	err := errors.New("cluster provisioning interrupted")
	if err != nil {
		return withResumeHint(err, "run 'openframe eks resume --cluster my-cluster' to continue")
	}
	return nil
}

// Elsewhere, when handling the error:
func handleError(err error) {
	var hinter interface{ ResumeHint() string }
	if errors.As(err, &hinter) {
		hint := hinter.ResumeHint()
		if hint != "" {
			// Display hint to the user even if Ctrl+C interrupted the operation
			println("Resume with:", hint)
		}
	}
}
```

Use `withResumeHint` whenever an operation can be interrupted (e.g., via Ctrl+C) and you need to guarantee the user still sees actionable resume instructions, since the generic interruption handler ignores `err.Error()`.
