# main.tf

Root Terraform module generated and owned by the OpenFrame CLI. It provisions a self-contained AWS EKS cluster consisting of a dedicated 2-AZ VPC with a single NAT gateway, an EKS cluster with one managed node group, core addons (`vpc-cni`, `kube-proxy`, `coredns`), and the AWS EBS CSI driver addon for persistent volume support. This module is not intended for manual editing — inputs are driven entirely by a generated `terraform.tfvars.json` file alongside it.

## Key Components

- **Provider config**: Pins `aws` provider to `>= 6.52, < 7.0` and Terraform `>= 1.15.0`; tags all resources with `openframe:cluster` and `openframe:managedBy`.
- **Variables**: `cluster_name`, `region`, `profile`, `kubernetes_version` (default `1.33`), `instance_type` (default `m7i-flex.large`, Free-Tier eligible), `min_nodes`/`max_nodes`/`desired_nodes`, `spot`.
- **`module.vpc`**: Uses `terraform-aws-modules/vpc/aws` v6.6.1 to create a `/16` VPC across 2 availability zones with public/private subnets and a single NAT gateway.
- **`module.eks`**: Uses `terraform-aws-modules/eks/aws` v21.24.1 (exact pin — see version-pinning rationale in file comments) to create the cluster, one managed node group with EBS CSI IAM policy attached, IMDS hop limit set to `2` (required for the CSI controller to reach IMDS), and explicit addon declarations since v21 disables addon auto-bootstrapping.
- **Outputs**: `cluster_name`, `cluster_endpoint`, `cluster_certificate_authority_data`, `region` — consumed by the CLI to generate a kubeconfig and manage the cluster lifecycle.

## Usage Example

This module is applied by the OpenFrame CLI, not run manually. A typical `terraform.tfvars.json` generated by the CLI looks like:

```hcl
# terraform.tfvars.json (generated by openframe-cli)
{
  "cluster_name"       = "openframe-dev"
  "region"             = "us-east-1"
  "kubernetes_version" = "1.33"
  "instance_type"      = "m7i-flex.large"
  "min_nodes"          = 1
  "max_nodes"          = 4
  "desired_nodes"      = 3
  "spot"               = false
}
```

```bash
# Applied internally by the CLI's provisioning workflow
terraform init
terraform apply -var-file="terraform.tfvars.json" -auto-approve
```

**Important:** Module versions in this file are exact pins (not `~>` ranges). Bumping `terraform-aws-modules/eks/aws` requires a deliberate version review and a full create/delete test pass, since past minor upgrades silently changed defaults (addon bootstrapping, IMDS hop limit) and broke cluster creation.
