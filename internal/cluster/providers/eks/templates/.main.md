# main.tf

Root Terraform module generated and owned by the OpenFrame CLI, provisioning a self-contained AWS EKS cluster with a dedicated 2-AZ VPC, a single managed node group, core EKS addons (vpc-cni, kube-proxy, coredns), and the EBS CSI driver. All configuration is driven by `terraform.tfvars.json` written alongside this file; it is not intended to be edited by hand.

## Key Components

- **Providers**: Pins `hashicorp/aws >= 6.52, < 7.0` and Terraform `>= 1.15.0`.
- **Input variables**: `cluster_name`, `region`, `profile`, `kubernetes_version` (default `1.33`), `instance_type` (default `m7i-flex.large`, Free-Tier-eligible), `min_nodes`/`max_nodes`/`desired_nodes`, and `spot`.
- **`module.vpc`** (`terraform-aws-modules/vpc/aws` v6.6.1): Creates a `/16` VPC across 2 availability zones with public/private subnets, a single NAT gateway, and ELB-role subnet tags.
- **`module.eks`** (`terraform-aws-modules/eks/aws` v21.24.1): Creates the EKS control plane with public endpoint access, creator admin permissions, one managed node group (with EBS CSI IAM policy and an IMDS hop limit of 2), and explicitly declared addons since v21 disables auto-bootstrapped addons.
- **Outputs**: `cluster_name`, `cluster_endpoint`, `cluster_certificate_authority_data`, `region` — consumed by the CLI to build a kubeconfig and identify the cluster for teardown.

Module versions are **exact pins** (not `~>` ranges) because a floating version once introduced breaking default changes (missing addons, restrictive IMDS hop limit, gated Kubernetes version data source).

## Usage Example

Typically invoked by the OpenFrame CLI, not run directly. Manual usage:

```hcl
# terraform.tfvars.json
{
  "cluster_name": "my-openframe-cluster",
  "region": "us-east-1",
  "kubernetes_version": "1.33",
  "instance_type": "m7i-flex.large",
  "min_nodes": 1,
  "max_nodes": 4,
  "desired_nodes": 3,
  "spot": false
}
```

```bash
terraform init
terraform apply -var-file=terraform.tfvars.json
```

After apply, retrieve the kubeconfig using the `cluster_endpoint` and `cluster_certificate_authority_data` outputs combined with `aws eks get-token` for authentication.
