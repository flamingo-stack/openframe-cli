# teardown.go

Implements the EKS teardown lifecycle for `openframe-cli`: gracefully releasing Kubernetes-managed cloud resources (EBS volumes, load balancers) **before** `terraform destroy` runs, and sweeping any orphaned EBS volumes **after** destroy completes. This two-phase approach prevents billable orphaned volumes and avoids `DependencyViolation` errors when Terraform tries to destroy a VPC that still has attached load balancer ENIs.

## Key Components

- **`releaseWorkloadResources(ctx, rec)`** — Pre-destroy step. Connects to the cluster, deletes all application namespaces (via `appNamespacesToDelete`), and polls (bounded by `resourceDrainTimeout`) until Delete-reclaim PersistentVolumes and app LoadBalancer Services are gone, giving the EBS CSI driver and cloud controller time to clean up. Fully best-effort — never blocks the overall destroy.
- **`sweepOrphanedVolumes(ctx, rec, force)`** (method on `Provider`) — Post-destroy step. Queries AWS for `available` EBS volumes tagged `openframe:cluster=<name>` and either deletes them (with `--force` or interactive confirmation) or reports a manual cleanup command.
- **`isSystemNamespace(ns)`** — Identifies cluster/system namespaces (`default`, `kube-system`, `kube-*`, `aws-*`, `amazon-*`) that must never be deleted.
- **`appNamespacesToDelete(all)`** — Filters out system namespaces and orders `argocd` first, so its controller stops reconciling before dependent workloads are removed.
- **`countDeletablePVs(pvs)`** / **`countAppLoadBalancers(svcs)`** — Helpers used by the drain-wait loop to detect when cleanup is complete.
- **`parseVolumeIDs(out)`** — Parses AWS CLI text output into a slice of volume IDs.
- **`printOrphanList` / `printOrphanCleanupHint`** — User-facing output for reporting orphaned volumes and manual cleanup steps.
- **Constants**: `orphanVolumeTagKey`, `resourceDrainTimeout` (5m), `kubeCallTimeout` (20s).

## Usage Example

```go
// Before running terraform destroy:
releaseWorkloadResources(ctx, rec)

// ... terraform destroy executes ...

// After destroy, sweep any orphaned EBS volumes:
provider.sweepOrphanedVolumes(ctx, rec, force)
```

Both functions are invoked internally by the EKS provider's teardown flow and are not intended for direct external use. `rec` is a `tfengine.Record` containing cluster name, AWS region, and profile metadata; `force` controls whether orphaned volumes are deleted without an interactive prompt.
