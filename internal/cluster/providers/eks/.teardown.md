# teardown.go

Implements pre- and post-destroy cleanup logic for EKS cluster teardown, ensuring EBS volumes and load balancers provisioned outside Terraform's state are properly released before and after cluster destruction.

## Key Components

- **`releaseWorkloadResources(ctx, rec)`** — Pre-destroy step that deletes all application namespaces (via Kubernetes API) and waits (bounded by `resourceDrainTimeout`) for Delete-reclaim PersistentVolumes and LoadBalancer Services to drain, allowing the EBS CSI driver and cloud controller to clean up volumes/ELBs before Terraform destroys the VPC and node group. Fully best-effort — never blocks the requested destroy.
- **`(p *Provider) sweepOrphanedVolumes(ctx, rec, force)`** — Post-destroy step that queries AWS for EBS volumes tagged with `orphanVolumeTagKey` matching the cluster name and still in `available` status, then deletes them with operator consent (`--force` flag or interactive confirmation), or reports them with a manual cleanup command.
- **`isSystemNamespace(ns)`** — Determines whether a namespace is a system/control-plane namespace that must never be deleted (via `systemNamespaces` map and `systemNamespacePrefixes`).
- **`appNamespacesToDelete(all)`** — Filters system namespaces out of a namespace list and orders `argocd` first, so GitOps reconciliation stops before managed workloads are deleted.
- **`countDeletablePVs(pvs)`** / **`countAppLoadBalancers(svcs)`** — Helper counters used as drain-completion signals (Delete-reclaim PVs remaining, non-system LoadBalancer Services remaining).
- **`parseVolumeIDs(out)`** — Parses `aws ec2 describe-volumes` text output into a slice of volume IDs.
- **`printOrphanList` / `printOrphanCleanupHint`** — User-facing output for reporting surviving volumes and the manual `aws ec2` cleanup command.

## Usage Example

```go
// Before running terraform destroy, release namespaced workloads
// so PVC-backed volumes and Service-backed load balancers drain first.
releaseWorkloadResources(ctx, record)

// ... run terraform destroy ...

// After destroy, sweep any EBS volumes left behind (outside Terraform state).
provider.sweepOrphanedVolumes(ctx, record, force)
```

Both functions are internal to the `eks` provider's teardown flow and are invoked automatically as part of the cluster deletion command — they are not intended to be called directly by CLI users.
