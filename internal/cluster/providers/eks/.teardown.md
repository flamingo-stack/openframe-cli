# teardown.go

Implements EKS cluster teardown safety mechanisms: pre-destroy Kubernetes resource release (draining PVC-backed volumes and LoadBalancer services) and post-destroy orphaned EBS volume detection/cleanup. This ensures cluster destruction doesn't leave billable cloud resources or fail due to dangling AWS dependencies.

## Key Components

- **`releaseWorkloadResources(ctx, rec)`** — Before terraform destroy, deletes all application namespaces (system namespaces like `kube-system` are preserved) so the EBS CSI driver and cloud controller can clean up backing EBS volumes and load balancers. Waits up to `resourceDrainTimeout` (5 min) for drain to complete; best-effort and never blocks the overall teardown.
- **`(*Provider) sweepOrphanedVolumes(ctx, rec, force)`** — After terraform destroy, queries AWS for EBS volumes tagged `openframe:cluster=<name>` with status `available` (i.e., orphaned). Deletes them if `force` is set or the user confirms interactively; otherwise prints a manual cleanup command.
- **`isSystemNamespace(ns)`** / **`systemNamespaces`** / **`systemNamespacePrefixes`** — Identify cluster/system namespaces that must never be deleted during teardown.
- **`appNamespacesToDelete(all)`** — Filters out system namespaces and orders `argocd` first, so its controller stops before workloads it manages are removed.
- **`countDeletablePVs(pvs)`** / **`countAppLoadBalancers(svcs)`** — Helpers used to detect when volume/load-balancer drain has completed (zero remaining).
- **`parseVolumeIDs(out)`** — Parses `aws ec2 describe-volumes` text output into a list of volume IDs.
- **`printOrphanList`** / **`printOrphanCleanupHint`** — User-facing messaging for orphaned volumes found post-destroy.
- **Constants**: `orphanVolumeTagKey` (tag used to find orphaned volumes), `resourceDrainTimeout` (5 min), `kubeCallTimeout` (20 s).

## Usage Example

```go
// Before running terraform destroy, release workload resources so
// EBS volumes and load balancers are cleaned up by in-cluster controllers.
releaseWorkloadResources(ctx, rec)

// ... terraform destroy runs here ...

// After destroy, sweep any EBS volumes left orphaned outside terraform state.
provider.sweepOrphanedVolumes(ctx, rec, force)
```

Both functions are internal to the `eks` package's teardown flow and are invoked as part of the cluster deletion sequence, ensuring no billable AWS resources or destroy-blocking dependencies survive after `openframe cluster delete`.
