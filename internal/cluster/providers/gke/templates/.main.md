# main.tf

Root Terraform module generated and managed by the OpenFrame CLI to provision a self-contained GKE cluster. It creates a dedicated VPC (with pod/service secondary IP ranges), a Cloud NAT for private-node egress, and a regional or zonal GKE cluster with a single autoscaling node pool. This file is not meant to be hand-edited — all inputs are supplied via `terraform.tfvars.json` alongside it, and the CLI orchestrates the full lifecycle (create/destroy).

## Key Components

- **`google` provider** — configured with `project`/`region` and default resource labels (`openframe-cluster`, `openframe-managed-by`) for tagging.
- **`module.network`** — uses `terraform-google-modules/network/google` to create a VPC and subnet with `pods`/`services` secondary ranges.
- **`google_compute_router` / `google_compute_router_nat`** — Cloud NAT setup enabling egress for private (no external IP) GKE nodes.
- **`module.gke`** — uses the `private-cluster` submodule of `terraform-google-modules/kubernetes-engine/google` to provision the cluster with a single autoscaling node pool (`min_nodes`/`max_nodes`/`desired_nodes`), private nodes, and a public API endpoint.
- **Variables** — `cluster_name`, `project`, `region`, `regional`, `zone`, `kubernetes_version`, `instance_type`, `min_nodes`, `max_nodes`, `desired_nodes`, `spot`.
- **Outputs** — `cluster_name`, `cluster_endpoint` (sensitive), `cluster_certificate_authority_data` (sensitive), `region`.

Notable design decisions (documented inline in the file):
- Project APIs (compute, container) are enabled by the CLI *outside* Terraform to avoid multi-cluster ownership conflicts on shared projects.
- Nodes are private for org-policy compliance; Cloud NAT provides egress; the API endpoint remains public for direct `kubectl` access.
- `deletion_protection = false` since the CLI must be able to run `openframe cluster delete`.
- Explicit `depends_on` on the network module/NAT ensures correct teardown ordering (avoids "subnetwork in use" errors on destroy).

## Usage Example

This module is invoked by the OpenFrame CLI, not typically run manually. A generated `terraform.tfvars.json` might look like:

```hcl
# terraform.tfvars.json (generated by openframe-cli)
cluster_name       = "openframe-dev"
project            = "my-gcp-project"
region             = "us-central1"
regional           = false
zone               = "us-central1-a"
kubernetes_version = "1.33"
instance_type      = "e2-standard-4"
min_nodes          = 1
max_nodes          = 4
desired_nodes      = 3
spot               = false
```

Applying via Terraform directly (for debugging):

```bash
terraform init
terraform apply -var-file="terraform.tfvars.json"
terraform output -raw cluster_endpoint
```
