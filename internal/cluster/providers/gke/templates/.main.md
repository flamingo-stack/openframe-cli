## Overview

Root Terraform module generated and managed by the OpenFrame CLI to provision a self-contained GKE cluster. It creates a dedicated VPC with pod/service secondary ranges, a Cloud NAT for private-node egress, and a regional or zonal GKE cluster with a single autoscaling node pool. This file is auto-generated — it should not be edited by hand; all inputs are supplied via `terraform.tfvars.json`.

## Key Components

- **`terraform` block** — pins Terraform `>= 1.15.0` and the `hashicorp/google` provider (`>= 7.17.0, < 8`).
- **Input variables** — `cluster_name`, `project`, `region`, `regional`, `zone`, `kubernetes_version`, `instance_type`, `min_nodes`, `max_nodes`, `desired_nodes`, `spot`.
- **`provider "google"`** — configures project/region and applies default resource labels for CLI ownership tracking.
- **`module.network`** — `terraform-google-modules/network/google`, creates a VPC, subnet, and `pods`/`services` secondary IP ranges.
- **`google_compute_router.nat` / `google_compute_router_nat.nat`** — Cloud NAT setup enabling egress for private (no external IP) GKE nodes.
- **`module.gke`** — `terraform-google-modules/kubernetes-engine/google//modules/private-cluster`, provisions the private GKE cluster with a single managed node pool (`default`), deletion protection disabled (so `openframe cluster delete` works), and explicit `depends_on` for correct teardown ordering.
- **Outputs** — `cluster_name`, `cluster_endpoint` (sensitive), `cluster_certificate_authority_data` (sensitive), `region`.

Notably, project API enablement (compute, container) is intentionally **not** managed here — the CLI enables these before running Terraform, avoiding ownership conflicts across multiple cluster workspaces sharing a project.

## Usage Example

This module is not meant to be invoked manually — the OpenFrame CLI generates `terraform.tfvars.json` and runs Terraform automatically. For reference, the CLI writes variables like this:

```hcl
# terraform.tfvars.json (generated by the CLI)
{
  "cluster_name": "my-openframe-cluster",
  "project": "my-gcp-project",
  "region": "us-central1",
  "regional": false,
  "zone": "us-central1-a",
  "kubernetes_version": "1.33",
  "instance_type": "e2-standard-4",
  "min_nodes": 1,
  "max_nodes": 4,
  "desired_nodes": 3,
  "spot": false
}
```

Equivalent manual invocation (for debugging only):

```bash
cd cluster-workspace/
terraform init
terraform apply -var-file=terraform.tfvars.json
```
