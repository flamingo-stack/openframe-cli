## teardown.go

Implements GKE cluster teardown safety measures to prevent orphaned Persistent Disks (PVC-provisioned volumes that live outside terraform state). It pre-drains workload namespaces before `terraform destroy` so the GKE CSI driver releases backing disks in time, and performs a post-destroy sweep to detect and optionally clean up any disks that survived.

## Key Components

- **`releaseWorkloadDisks`** — Best-effort pre-destroy step that deletes application namespaces (argocd first) so PVC-backed disks are released by the CSI driver before the node pool is torn down; bounded by `diskDrainTimeout`.
- **`isSystemNamespace` / `appNamespacesToDelete`** — Filters out cluster/system namespaces (`kube-system`, `gke-`, `gmp-`, etc.) that must survive teardown, returning only application namespaces to delete.
- **`countDeletablePVs`** — Counts PersistentVolumes with a `Delete` reclaim policy, used as the drain-completion signal.
- **`(*Provider).sweepOrphanedDisks`** — Post-destroy scan via `gcloud compute disks list` for disks still labeled with the deleted cluster's name, scoped to the cluster's region/zone to avoid cross-cluster collisions; deletes them with consent (`--force` or interactive prompt) or prints a manual cleanup hint.
- **`disksInLocation`** — Filters discovered disks to those actually belonging to the target cluster's location (zone/region), since GKE cluster names are unique per location, not per project.
- **`parseDisks`** — Parses tab-separated `gcloud` output into `disk` structs, preserving empty columns to correctly distinguish zonal vs. regional disks.
- **`printOrphanList` / `printOrphanCleanupHint`** — User-facing reporting for surviving disks and the manual `gcloud` command to remove them.

## Usage Example

```go
// Before terraform destroy: attempt to drain PVC-backed disks
releaseWorkloadDisks(ctx, tfRecord)

// ... run terraform destroy ...

// After destroy: sweep for any disks that didn't drain in time
provider.sweepOrphanedDisks(ctx, projectID, clusterName, region, forceFlag)
```

Both functions are designed to be non-blocking and best-effort: failures (unreachable cluster, RBAC errors, timeouts) are logged at debug/warning level rather than aborting the teardown, ensuring infrastructure destruction always completes while surfacing any billable leftovers to the operator.
