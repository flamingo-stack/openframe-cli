Provides Windows-specific WSL2 guidance errors for cluster operations that cannot execute from native Windows processes.

## Key Components

- **`ErrWindowsNeedsWSL`** — Sentinel error indicating cluster operations require WSL on Windows; wraps a descriptive message and can be matched with `errors.Is`.
- **`WSLClusterHint(operation string) error`** — OS-aware guard function; returns `nil` on non-Windows hosts or a formatted WSL guidance error on Windows. Intended for use as an early-return check before any cluster operation.
- **`windowsWSLError(operation string) error`** — Internal helper that builds the detailed user-facing error message including `wsl -d Ubuntu` instructions. Kept separate from `WSLClusterHint` to allow unit testing independent of the host OS.

## Usage Example

```go
// Guard a cluster operation at the start of a command handler
if err := platform.WSLClusterHint("wait for ArgoCD"); err != nil {
    return err
}

// Check for the sentinel error upstream if needed
if errors.Is(err, platform.ErrWindowsNeedsWSL) {
    // surface WSL-specific guidance in the UI
}
```

**Example error output on Windows:**

```text
wait for ArgoCD: cluster operations require running OpenFrame inside WSL on Windows

On Windows the Kubernetes cluster (Docker + k3d) runs inside WSL2, and OpenFrame
reaches it through the native Kubernetes client — which cannot connect from a
native Windows process. Run OpenFrame inside WSL instead:

    wsl -d Ubuntu
    openframe <your command>

Or perform the step manually with kubectl from inside WSL
```

> **Note:** `WSLClusterHint` depends on `IsWindows()` from the same `platform` package. On Linux/macOS it is always a no-op.
