## interfaces.go

Defines the core interfaces and installation request model for the chart subsystem, deliberately scoped to only the abstractions that are actually implemented and consumed—avoiding speculative service-locator patterns.

## Key Components

- **`ClusterLister`** — Interface for listing available clusters (`ListClusters()`).
- **`ClusterAccess`** — Extends `ClusterLister` with `GetRestConfig(name string)`, giving the chart (app) subsystem read-only cluster access without depending on cluster-creation logic. Implementations are injected by the composition root to keep subsystems decoupled.
- **`ArgoCDService`** — Manages ArgoCD lifecycle: `Install`, `IsInstalled`, `GetStatus`, `WaitForApplications`.
- **`AppOfAppsService`** — Manages app-of-apps chart lifecycle: `Install`, `IsInstalled`, `GetStatus`.
- **`GitRefValidator`** — Validates that a given git ref exists remotely (`ValidateRef`) before installation proceeds, catching typo'd `--ref` values early.
- **`InstallationRequest`** — Struct aggregating all parameters needed for a chart installation, including GitHub source config, kube context/config, cluster access, and behavioral flags like `NonInteractive`, `RequireExistingValues`, and `SyncStragglersOnStall`.

## Usage Example

```go
func installAppOfApps(ctx context.Context, appSvc types.AppOfAppsService, req types.InstallationRequest) error {
    installed, err := appSvc.IsInstalled(ctx, "argocd")
    if err != nil {
        return err
    }
    if installed && !req.Force {
        return nil
    }

    cfg := config.ChartInstallConfig{
        // populate from req.GitHubRepo, req.GitHubBranch, etc.
    }
    return appSvc.Install(ctx, cfg)
}

// Resolving cluster access via the injected interface
func resolveRestConfig(access types.ClusterAccess, clusterName string) (*rest.Config, error) {
    clusters, err := access.ListClusters()
    if err != nil {
        return nil, err
    }
    _ = clusters
    return access.GetRestConfig(clusterName)
}
```

These interfaces are typically implemented by concrete services in the `chart` package and wired together by the composition root (`cmd`/bootstrap layer), which is the only layer allowed to depend on both the chart and cluster subsystems.
