## Purpose

Defines the core interface contracts and the shared `InstallationRequest` data type for the chart subsystem. It establishes a minimal, purposefully small set of interfaces (post-audit cleanup) that decouple the chart/app installation logic from the cluster-creation subsystem and from concrete ArgoCD/App-of-Apps implementations.

## Key Components

- **`ClusterLister`** – interface for listing available clusters (`ListClusters`).
- **`ClusterAccess`** – extends `ClusterLister` with `GetRestConfig`, giving read-only cluster access to the app subsystem without depending on cluster-creation code. Concrete implementation is injected by the composition root.
- **`ArgoCDService`** – manages ArgoCD lifecycle: `Install`, `IsInstalled`, `GetStatus`, `WaitForApplications`.
- **`AppOfAppsService`** – manages app-of-apps chart lifecycle: `Install`, `IsInstalled`, `GetStatus`.
- **`GitRefValidator`** – validates that a given git ref (`--ref`) exists remotely before installation begins, via `ValidateRef`.
- **`InstallationRequest`** – struct aggregating all parameters needed for a chart installation, including CLI flags (`Force`, `DryRun`, `Verbose`), GitHub source config (`GitHubRepo`, `GitHubBranch`, `GitHubRefExplicit`), cluster targeting (`KubeConfig`, `KubeContext`, `ClusterAccess`), and behavioral flags (`NonInteractive`, `RequireExistingValues`, `SyncStragglersOnStall`).

## Usage Example

```go
func RunInstall(req types.InstallationRequest, argo types.ArgoCDService, appOfApps types.AppOfAppsService) error {
	ctx := context.Background()

	installed, err := argo.IsInstalled(ctx)
	if err != nil {
		return err
	}
	if !installed {
		if err := argo.Install(ctx, config.ChartInstallConfig{ /* ... */ }); err != nil {
			return err
		}
	}

	if req.ClusterAccess != nil {
		clusters, err := req.ClusterAccess.ListClusters()
		if err != nil {
			return err
		}
		_ = clusters
	}

	return appOfApps.Install(ctx, config.ChartInstallConfig{ /* ... */ })
}
```

## Notes

This file intentionally excludes speculative interfaces (e.g., `ServiceFactory`, `ServiceOrchestrator`, `WorkflowExecutor`) that had no implementations or callers, keeping the `types` package aligned with actual usage.
