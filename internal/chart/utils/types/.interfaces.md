## interfaces.go

Defines the core interfaces and request DTO for the chart installation subsystem. This file intentionally contains only interfaces with real implementations and callers—following an audit (B7) that removed 13 speculative service-locator interfaces with no concrete usage.

## Key Components

- **`ClusterLister`** – Minimal interface for listing available clusters (`ListClusters()`).
- **`ClusterAccess`** – Extends `ClusterLister` with `GetRestConfig(name string)`, giving the chart subsystem read-only cluster access without depending on cluster-creation logic. This keeps the app/chart subsystem decoupled from the cluster subsystem; only the composition root wires in the concrete implementation.
- **`ArgoCDService`** – Manages ArgoCD lifecycle: `Install`, `IsInstalled`, `GetStatus`, and `WaitForApplications`.
- **`AppOfAppsService`** – Manages the app-of-apps pattern lifecycle: `Install`, `IsInstalled`, `GetStatus`.
- **`GitRefValidator`** – Validates that a given git ref (`--ref`) exists in the remote repository before installation begins, avoiding late failures after ArgoCD is already installed.
- **`InstallationRequest`** – Struct aggregating all parameters needed to drive a chart installation, including GitHub source config, kube context/config, feature flags (`Force`, `DryRun`, `NonInteractive`, etc.), and an injected `ClusterAccess` for resolving install targets.

## Usage Example

```go
func RunInstall(req types.InstallationRequest, argocd types.ArgoCDService) error {
	ctx := context.Background()

	installConfig := config.ChartInstallConfig{
		// ... populated from req
	}

	if err := argocd.Install(ctx, installConfig); err != nil {
		return err
	}

	return argocd.WaitForApplications(ctx, installConfig)
}

// Composition root wires ClusterAccess implementation
req := types.InstallationRequest{
	GitHubRepo:     "flamingo-stack/openframe-helm",
	GitHubBranch:   "main",
	NonInteractive: true,
	ClusterAccess:  clusterAccessImpl,
}
```

Consumers depend only on these interfaces (not concrete types), enabling the composition root (`cmd`/bootstrap) to inject implementations while keeping subsystem boundaries clean per requirements 18/19.
