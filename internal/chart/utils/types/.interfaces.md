Defines the core interfaces and data structures used for chart installation orchestration within the OpenFrame CLI's types package.

## Key Components

### Interfaces

| Interface | Purpose |
|-----------|---------|
| `ClusterLister` | Single-method interface for listing available clusters |
| `ClusterAccess` | Extends `ClusterLister`; adds `GetRestConfig` to resolve a `*rest.Config` for a named cluster without importing cluster-creation code |
| `ArgoCDService` | Manages ArgoCD lifecycle: install, status checks, and application wait |
| `AppOfAppsService` | Manages app-of-apps chart lifecycle: install, installed checks, and status |

### Structs

**`InstallationRequest`** — aggregates all parameters for a chart installation operation, including:
- `Args`, `Force`, `DryRun`, `Verbose` — general control flags
- `GitHubRepo`, `GitHubBranch`, `GitHubRefExplicit` — source ref pinning
- `NonInteractive`, `RequireExistingValues` — interactive/upgrade behavior guards
- `SyncStragglersOnStall` — handles OutOfSync-but-healthy ArgoCD apps during upgrades
- `KubeConfig`, `KubeContext` — ensures the helm CLI, native client, and ArgoCD wait all target the same cluster
- `ClusterAccess` — injected by the composition root to satisfy the app/cluster subsystem boundary

## Usage Example

```go
req := types.InstallationRequest{
    GitHubRepo:            "flamingo-stack/openframe-helm",
    GitHubBranch:          "main",
    GitHubRefExplicit:     true,
    NonInteractive:        false,
    RequireExistingValues: true,
    KubeContext:           "my-cluster",
    ClusterAccess:         myClusterAccessImpl,
}

// Pass to install orchestration
if err := installer.Run(ctx, req); err != nil {
    log.Fatal(err)
}
```

## Architecture Notes

`ClusterAccess` is the dependency-inversion boundary between the chart (app) subsystem and the cluster subsystem. The composition root (in `cmd/` or bootstrap) injects a concrete implementation, keeping chart services free of cluster-creation imports per requirements 18/19.
