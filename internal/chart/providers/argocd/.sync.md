## Purpose

This file implements ArgoCD's "force-sync" mechanism for OpenFrame CLI, allowing a manual re-read of git and rollout of the root app-of-apps `Application` (and its children) without changing the target revision. It's used when auto-sync is disabled or the repo-server is serving stale manifests, driving sync purely through Kubernetes CRD patches rather than the ArgoCD CLI or API.

## Key Components

- **`RefreshAndSync(ctx, prune)`** — Top-level entry point. Applies a hard-refresh annotation patch to the `argocd-apps` root Application, waits for it to clear, ensures no operation is already running, triggers a sync via the `.operation` field, then syncs child Applications.
- **`syncChildApplications(ctx, prune)`** — Discovers child Applications owned by the root (via ArgoCD's label/annotation resource-tracking markers), groups them by deploy-order, and syncs group-by-group with health gating.
- **`trackingOwner(labels, annotations)`** — Resolves the owning Application name from either the `app.kubernetes.io/instance` label or the `argocd.argoproj.io/tracking-id` annotation.
- **`groupChildren(children)`** — Buckets child Applications by the `openframe.io/sync-group` label into ordered `syncGroup` values, falling back to a single ungated group for legacy manifests without the label.
- **`syncGroup`** — Struct pairing a group number with its sorted Application names.
- **Constants**: `refreshAnnotationKey`, `AppOfAppsName`, `refreshHardPatch`, `SyncGroupLabel`, `defaultSyncGroup`, `defaultGroupWait`, `trackingInstanceLabel`, `trackingIDAnnotation`.
- **`syncOperationPatch(prune)`** — Builds the JSON merge-patch that triggers ArgoCD's sync operation, with `prune` controlling resource deletion (off by default for safety).

## Usage Example

```go
mgr := &Manager{ /* initialized with kube config */ }

// Force ArgoCD to re-read git and roll out the moved ref,
// without pruning resources removed from git.
if err := mgr.RefreshAndSync(context.Background(), false); err != nil {
    log.Fatalf("force-sync failed: %v", err)
}
```

This is typically invoked from the `app upgrade --sync` CLI path when auto-sync is off or manifests appear stale, cascading the refresh and sync from the root `argocd-apps` Application down through its labeled sync groups.
