## sync.go

Implements ArgoCD force-sync logic for the root app-of-apps Application, driving refresh and sync operations directly through the Kubernetes dynamic client (bypassing the `argocd` CLI/API). It handles cascading sync of child Applications in dependency-ordered groups, using ArgoCD's resource-tracking markers to identify ownership.

## Key Components

- **`AppOfAppsName`** – the root Application (`argocd-apps`) that owns the whole platform; refreshing/syncing it cascades to all children.
- **`RefreshAndSync(ctx, prune)`** – forces a hard git refresh on the root app, waits for the refresh annotation to clear, ensures no operation is already running, triggers a sync via a `.operation` patch, then syncs child Applications. `prune` controls whether ArgoCD deletes resources removed from git (off by default).
- **`syncOperationPatch(prune)`** / **`refreshHardPatch`** – build the JSON merge patches used to trigger a hard refresh and a sync operation.
- **`trackingOwner(labels, annotations)`** – resolves the owning Application name from ArgoCD's label (`app.kubernetes.io/instance`) or annotation (`argocd.argoproj.io/tracking-id`) resource-tracking markers.
- **`syncChildApplications(ctx, prune)`** – lists and syncs child Applications owned by the root, falling back to syncing all non-root apps if no tracking markers are found. Reports partial failures instead of silently succeeding.
- **`groupChildren(children)`** – buckets children by `SyncGroupLabel` (`openframe.io/sync-group`) into ordered deploy groups, defaulting ungrouped/legacy children to `defaultSyncGroup` (3).
- **`syncGroup`** – struct pairing a group number with its sorted member names, used to sync groups lowest-first, gated on the previous group's health (bounded by `defaultGroupWait`, best-effort).

## Usage Example

```go
manager := argocd.NewManager(kubeConfig, 30*time.Second)

// Force ArgoCD to re-read git and roll out a moved branch ref,
// without deleting resources removed from git.
if err := manager.RefreshAndSync(ctx, false /* prune */); err != nil {
    log.Fatalf("refresh and sync failed: %v", err)
}

// After triggering, wait for readiness using the manager's own
// WaitForApplications gate (authoritative, independent of grouping).
```

Typically invoked from the `app upgrade --sync` (force-sync) CLI path when auto-sync is disabled or the repo-server is serving stale manifests for a floating git ref.
