## sync.go

Implements ArgoCD "force-sync" logic for the OpenFrame CLI: forces a hard refresh of the root app-of-apps `Application` and triggers a group-ordered sync of its child Applications via the Kubernetes dynamic client, without going through the `argocd` CLI or API server.

## Key Components

- **`RefreshAndSync(ctx, prune)`** — Entry point for force-sync mode of `app upgrade`. Patches the root Application (`argocd-apps`) with a hard-refresh annotation, waits for ArgoCD to clear it, guards against clobbering an in-flight operation, triggers a sync via the `.operation` field, then cascades to child Applications.
- **`syncChildApplications(ctx, prune)`** — Discovers children of the root app using ArgoCD's resource-tracking label/annotation, groups them by `SyncGroupLabel`, and syncs group-by-group (lowest number first), gating each group on the previous one's health.
- **`trackingOwner(labels, annotations)`** — Resolves the owning Application name from either the `app.kubernetes.io/instance` label or the `argocd.argoproj.io/tracking-id` annotation.
- **`groupChildren(children)`** — Buckets child Applications by their `SyncGroupLabel` value, returning sorted groups and whether any child was labeled (legacy manifests fall back to a single ungated group).
- **`syncOperationPatch(prune)`** — Builds the JSON merge-patch for `.operation.sync`, mirroring what `argocd app sync` does under the hood.
- **Constants** — `refreshAnnotationKey`, `AppOfAppsName`, `refreshHardPatch`, `SyncGroupLabel`, `defaultSyncGroup`, `defaultGroupWait`, `trackingInstanceLabel`, `trackingIDAnnotation` document the ArgoCD conventions this file depends on.

## Usage Example

```go
mgr := argocd.NewManager( /* ... */ )

// Force ArgoCD to re-read git for a moved branch ref and roll it out,
// without deleting resources removed from git (prune=false).
if err := mgr.RefreshAndSync(ctx, false); err != nil {
    log.Fatalf("force-sync failed: %v", err)
}

// Enable pruning when resources removed from git should also be deleted.
if err := mgr.RefreshAndSync(ctx, true); err != nil {
    log.Fatalf("force-sync with prune failed: %v", err)
}
```

This is typically invoked from the `app upgrade --sync` command path when auto-sync is disabled or the repo-server is suspected of serving stale cached manifests. `WaitForApplications` (elsewhere in the package) remains the authoritative readiness check after this call returns.
