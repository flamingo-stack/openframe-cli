## Overview

`wait.go` implements the ArgoCD application readiness polling logic used during platform chart installation. It exposes `WaitForApplications`, which blocks until all ArgoCD applications reach `Healthy` + `Synced` status, while providing rich terminal feedback (spinner, live dashboard, or plain log lines), health checks, stall/stuck-application detection, repo-server recovery, and deterministic error diagnostics on timeout or cancellation.

## Key Components

- **`Manager.WaitForApplications(ctx, config)`** — Main entry point. Performs a bootstrap wait with cluster connectivity checks, then enters a monitoring loop that polls ArgoCD application status until all apps are healthy/synced, times out, or the context is cancelled.
- **Display modes** — Chooses between a live `appDashboard` (interactive, non-verbose), a `uispinner.Spinner` (default), or plain `pterm` log lines (`--silent`), each mutually exclusive and nil-guarded.
- **`waitNote` helper** — Routes ad-hoc status announcements either into the dashboard's note area or through the standard printer (important for CI `::warning::` annotations).
- **Repo-server health handling** — Uses `checkRepoServerHealth`, `repoServerAge`, and `triggerRepoServerRecovery` to detect and recover from crash-looping or OOM-killed repo-server pods, respecting a cold-start grace period.
- **Stall/degradation trackers** — `newStallTracker`, `newFatalManifestTracker`, `newDegradedTracker` detect per-application stalls, deterministic manifest errors, and terminally degraded pods to fail fast instead of waiting for the full timeout.
- **Deadline management** — `capToDeadline` ensures the wait timeout never exceeds the caller's context deadline, enabling meaningful diagnostics instead of a bare "context deadline exceeded".
- **Cluster health monitoring** — `checkClusterConnectivity` and `printClusterDiagnostics` detect cluster unavailability during bootstrap and the main loop, aborting early after repeated consecutive failures.
- **Last-known-state tracking** — Maintains `lastNotReadyApps`, `lastNotReadyNames`, `lastNotReadyDetails`, and `lastAppsSeen` so cancellation or timeout errors report exactly which applications were pending and why.

## Usage Example

```go
mgr := argocd.NewManager(executor, platformClient)
mgr.SetWaitTimeout(45 * time.Minute)

cfg := config.ChartInstallConfig{
    ClusterName: "openframe-dev",
    Verbose:     true,
    Silent:      false,
}

ctx, cancel := context.WithTimeout(context.Background(), time.Hour)
defer cancel()

if err := mgr.WaitForApplications(ctx, cfg); err != nil {
    log.Fatalf("ArgoCD applications did not become ready: %v", err)
}
```

This is typically invoked after ArgoCD and the app-of-apps manifest have been installed, as the final readiness gate before reporting a successful platform installation.
