## degraded.go

Implements fail-fast detection for ArgoCD applications stuck in a terminal `Degraded`+`Synced` state, avoiding long silent timeouts when a workload's progress deadline has already passed and it cannot self-heal.

## Key Components

- **`degradedFailAfter()`** – Returns the duration an app must remain continuously Degraded+Synced before being flagged as a fail-fast candidate. Defaults to 8 minutes; overridable via the `OPENFRAME_DEGRADED_FAIL_AFTER` environment variable (Go duration format, e.g. `"5m"`).
- **`degradedMinChecks`** – Minimum number of consecutive observations required before the wall-clock threshold can trigger, preventing false positives from sparse polling gaps.
- **`degradedRecheckInterval`** – Throttles re-reporting of a persistent candidate (1 minute) to avoid re-running expensive pod diagnostics on every poll cycle.
- **`degradedTracker`** / **`degradedEntry`** – Per-application state tracker recording how long an app has stayed Degraded+Synced, resetting the clock when the app recovers, changes state, or disappears.
- **`newDegradedTracker()`** – Constructs a tracker initialized with the configured fail-after duration.
- **`(*degradedTracker).observe(apps, now)`** – Scans applications, updates tracking state, and returns those that have crossed both the minimum-checks and duration thresholds and are due for re-reporting. Results are sorted by name for deterministic output.
- **`degradedAppError(apps, diag)`** – Builds a descriptive, self-diagnosed error listing the stuck applications and embedding pod-level diagnostic output (crash logs/events) explaining *why* the app is stuck.

## Usage Example

```go
tracker := newDegradedTracker()

for {
    apps := fetchApplications() // poll ArgoCD
    candidates := tracker.observe(apps, time.Now())

    for _, app := range candidates {
        if terminal, diag := diagnoseFailingApps(app); terminal {
            return degradedAppError([]Application{app}, diag)
        }
    }

    time.Sleep(2 * time.Second)
}
```

This pattern is used inside the ArgoCD wait loop: `observe` identifies long-stuck Degraded apps, and only after the caller confirms a genuinely stuck pod (via `diagnoseFailingApps`) does it abort with a diagnostic error instead of waiting out the full timeout.
