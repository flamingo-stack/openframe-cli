## applications.go

Core data model and Kubernetes client initialization for the ArgoCD `Manager`, which manages ArgoCD `Application` custom resources for the OpenFrame CLI. It defines the `Manager` type used across the `argocd` package to poll, sync, and inspect ArgoCD applications, using native Kubernetes clients (dynamic, apiextensions, core) rather than shelling out to `kubectl` or `argocd` where possible.

## Key Components

- **`Manager`** — Central struct holding a `CommandExecutor`, optional cluster name, native Kubernetes clients (`kubeClient`, `apiextClient`, `dynamicClient`), and various tunable timeouts/wait durations (`waitTimeout`, `syncWait`, `groupWait`, `podWaitTimeout`, etc.) used by other files in the package for orchestration and testing overrides.
- **`applicationGVR`** — `schema.GroupVersionResource` identifying ArgoCD's `applications.argoproj.io/v1alpha1` CRD, used with the dynamic client instead of importing the argo-cd Go module.
- **`NewManager`, `NewManagerWithCluster`, `NewManagerWithConfig`** — Constructors for `Manager`, with `NewManagerWithConfig` being preferred when a `*rest.Config` is already available (e.g., right after k3d cluster creation). Applies insecure TLS handling for local clusters.
- **`initKubernetesClients`** — Lazily builds a `rest.Config` from kubeconfig (with optional explicit cluster context and Windows `host.docker.internal` normalization), then initializes `kubeClient`, `apiextClient`, and `dynamicClient`.
- **`getKubeconfigPath`** — Resolves the kubeconfig path from `$KUBECONFIG` or the default `~/.kube/config`.
- **`SetClusterName`** — Sets the explicit cluster context name on the manager.
- **`Application` / `ResourceIssue`** — Public structs representing an ArgoCD app's health, sync, condition, and operation status, plus any unhealthy child resources.
- **`argoApp`** — Internal struct mirroring the relevant subset of ArgoCD's Application JSON schema, used for `kubectl`-based and dynamic-client-based parsing.
- **`argoAppFromObject`** — Converts an unstructured dynamic-client object into an `argoApp` via JSON round-trip, ensuring both access paths share identical parsing logic.

## Usage Example

```go
import (
    "github.com/flamingo-stack/openframe-cli/internal/chart/argocd"
    "github.com/flamingo-stack/openframe-cli/internal/shared/executor"
)

exec := executor.NewCommandExecutor()

// Preferred: reuse an existing rest.Config from cluster creation
mgr, err := argocd.NewManagerWithConfig(exec, restConfig)
if err != nil {
    log.Fatal(err)
}

// Optionally override wait timeout for a faster force-sync
mgr = mgr.WithWaitTimeout(10 * time.Minute)

// Or construct lazily with just a cluster name; clients init on first use
mgr2 := argocd.NewManagerWithCluster(exec, "k3d-openframe")
```
