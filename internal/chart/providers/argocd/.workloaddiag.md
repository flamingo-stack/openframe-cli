## workloaddiag.go

Provides workload-level diagnostics for ArgoCD applications stuck in a `Degraded` state despite being `Synced`. When manifests apply successfully but a pod is unhealthy, this file inspects the pod's containers, pulls crash logs, and gathers recent warning events so failures surface with an actionable root cause instead of a generic timeout.

## Key Components

- **`failingContainers(pod)`** – Pure function that scans a pod's init/main container statuses and returns `containerIssue` entries for containers that are waiting on an error reason, terminated non-zero, or crash-looping (detected via restart count + last termination state).
- **`containerIssue`** – Struct describing a single failing container: pod, container, image, reason, restart count, and whether it's `terminal` (won't self-recover).
- **`terminalWaitingReasons`** – Set of waiting reasons (e.g. `CrashLoopBackOff`, `ImagePullBackOff`) considered non-recoverable.
- **`isImagePullReason(reason)`** – Detects image-pull-related failure reasons to surface a registry-credentials hint.
- **`(*Manager).appPods(ctx, ns, appName)`** – Lists pods for an app via ArgoCD tracking labels, falling back to the whole namespace; returns an `owned` flag indicating attribution confidence.
- **`(*Manager).diagnoseFailingApps(ctx, apps)`** – Main entry point: builds a human-readable diagnostic report (failing pods, reasons, log tails, warning events) and returns the subset of apps confirmed "stuck" (terminal + attributable failures), enabling fail-fast behavior.
- **`(*Manager).lastPodLogs(ctx, ns, pod, container, previous)`** – Fetches the last N log lines from a container, optionally from its previous (crashed) instance.
- **`(*Manager).recentWarningEvents(ctx, ns)`** – Returns the most recent Kubernetes `Warning` events in a namespace, newest first, bounded to `diagMaxEvents`.
- **`indentLines(s, prefix)`** – Utility to indent multi-line strings for report formatting.

## Usage Example

```go
// Given a Manager with an initialized kubeClient and a list of
// Degraded-but-Synced ArgoCD applications:
diagText, stuckApps := manager.diagnoseFailingApps(ctx, candidateApps)

if len(stuckApps) > 0 {
    // At least one app has a workload that won't recover on its own
    // (CrashLoopBackOff, ImagePullBackOff, repeated crashes).
    fmt.Println("Fail-fast triggered, diagnostic:")
    fmt.Println(diagText)
    return fmt.Errorf("installation stuck: %d app(s) failing", len(stuckApps))
}
```

This is typically invoked from the health-check/reconciliation loop when apps remain `Degraded` past an initial grace period, letting the CLI report *why* an install is hanging (e.g. missing registry credentials) instead of waiting out the full timeout.
