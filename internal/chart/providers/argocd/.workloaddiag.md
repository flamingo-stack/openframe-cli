## workloaddiag.go

Provides workload-level diagnostics for ArgoCD applications stuck in a `Degraded` state. When an app's manifests are successfully synced but its pods are unhealthy, this file inspects the underlying Kubernetes pods to surface the actual root cause—crash logs, image pull errors, and warning events—turning a silent timeout into an actionable error message.

## Key Components

- **`failingContainers(pod)`** — Pure function that inspects a pod's container statuses and returns any containers in an error state (waiting with an error reason, terminated non-zero, or crash-looping between restarts).
- **`containerIssue`** — Struct describing a single failing container: pod/container name, image, failure reason, restart count, and whether it's `terminal` (won't self-recover).
- **`terminalWaitingReasons`** — Map of container waiting reasons (`CrashLoopBackOff`, `ImagePullBackOff`, etc.) considered unrecoverable.
- **`isImagePullReason(reason)`** — Detects image-pull-related failures to attach a registry-credentials hint.
- **`(*Manager) appPods(ctx, ns, appName)`** — Resolves pods belonging to an app via ArgoCD tracking labels, falling back to the whole namespace; reports whether the result is confidently attributable (`owned`).
- **`(*Manager) diagnoseFailingApps(ctx, apps)`** — Main entry point: builds a human-readable diagnostic string per app (failing pods, reasons, log excerpts, warning events) and returns the subset of apps that are definitively `stuck` (terminal failure in owned pods), enabling fail-fast behavior instead of waiting out a timeout.
- **`(*Manager) lastPodLogs(ctx, ns, pod, container, previous)`** — Fetches the tail of a container's current or previous (crashed) log stream.
- **`(*Manager) recentWarningEvents(ctx, ns)`** — Lists the most recent `Warning` Kubernetes events in a namespace, newest first.
- **`indentLines(s, prefix)`** — Helper to indent multi-line diagnostic text for readability.

## Usage Example

```go
// Inside an ArgoCD sync-wait loop, once apps are found Degraded:
diagText, stuckApps := manager.diagnoseFailingApps(ctx, degradedApps)

if len(stuckApps) > 0 {
    // At least one app has a workload that will not recover on its own
    // (CrashLoopBackOff, ImagePullBackOff, etc.) — fail fast instead of
    // waiting for the full timeout.
    return fmt.Errorf("application(s) stuck in unrecoverable state:%s", diagText)
}

// Otherwise, log the diagnostic and continue waiting for sync.
log.Info(diagText)
```

This is typically invoked from the ArgoCD sync-status polling logic when applications report `Degraded`, giving operators immediate insight (e.g., "CrashLoopBackOff, image pull failed—missing registry credentials") rather than a generic timeout error.
