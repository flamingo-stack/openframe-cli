Filters subprocess log output to remove informational logrus/logfmt noise from error messages, ensuring only actionable lines (warnings, errors, fatals) surface to the user.

## Key Components

| Symbol | Type | Description |
|--------|------|-------------|
| `logrusInfoLine` | `*regexp.Regexp` | Matches colored/TTY logrus `INFO`, `DEBU`, `TRAC` lines (e.g., `INFO[0007] ...`) |
| `logfmtInfoLine` | `*regexp.Regexp` | Matches plain logfmt records with `level=info/debug/trace` |
| `stripLogNoise` | `func` | Splits output line-by-line, drops matched informational records, rejoins the rest |
| `errorDetail` | `func` | Orchestrates noise stripping, fallback to raw text, and tail-truncation before embedding in error messages |

## Usage Example

```go
// Inside the executor when a subprocess fails:
stderr := "INFO[0000] Pulling image...\nINFO[0003] Starting node...\nERRO[0005] Failed to bind port 6443"

detail := errorDetail(stderr)
// → "ERRO[0005] Failed to bind port 6443"

// Fallback: if only INFO lines existed, raw stderr is preserved
infoOnly := "INFO[0000] Creating cluster...\nINFO[0001] Done"
detail = errorDetail(infoOnly)
// → "INFO[0000] Creating cluster...\nINFO[0001] Done"  (raw, nothing dropped)
```

## Notes

- **Scope**: Targets k3d's logrus-formatted stderr specifically. Helm and Docker use different logging formats and are unaffected.
- **Fallback safety**: If stripping removes all content (e.g., the process only logged info before crashing), `errorDetail` falls back to the raw text to avoid silent data loss.
- **Truncation**: Output exceeding `maxStderrInError` bytes is tail-truncated (prefix `"..."`) — the failure reason typically appears at the end of stderr.
