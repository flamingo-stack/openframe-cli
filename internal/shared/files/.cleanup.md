# cleanup.go

Provides backup and restore functionality for files modified by the CLI, ensuring that any changes made during CLI operations can be safely reverted on error, interruption, or as part of temporary file cleanup after success.

## Key Components

- **`FileBackup`** - Struct representing a single backup entry: original path, optional backup file path or in-memory content, and whether the file existed before modification.
- **`FileCleanup`** - Manager that tracks a list of `FileBackup` entries and coordinates restore/cleanup operations.
- **`NewFileCleanup()`** - Constructor for a new `FileCleanup` instance.
- **`RestoreFiles(verbose bool) error`** - Forcibly restores all backed-up files; intended for error/interruption handling.
- **`RestoreFilesOnSuccess(verbose bool) error`** - Restores files only after successful completion.
- **`RestoreFilesWithResult(verbose bool, success bool) error`** - Restores files conditionally based on operation success, respecting `cleanupOnSuccess` mode for temporary files.
- **`RegisterTempFile(filePath string) error`** - Registers a newly created temporary file so it is removed during restore.
- **`SetCleanupOnSuccessOnly(enabled bool)`** - Configures whether temp files should only be cleaned up on success.
- **`restoreFile`, `cleanupBackupFiles`, `copyFile`** - Internal helpers for restoring individual files, removing physical backup files (skipping any whose restore failed), and copying file contents.

## Usage Example

```go
cleanup := files.NewFileCleanup()

// Register a temp file created during the operation
if err := cleanup.RegisterTempFile("/tmp/openframe-config.yaml"); err != nil {
    log.Fatal(err)
}

defer func() {
    if r := recover(); r != nil {
        // Interruption or panic: force restore
        cleanup.RestoreFiles(true)
        panic(r)
    }
}()

// ... perform CLI operations ...

// On successful completion, clean up temp files
if err := cleanup.RestoreFilesOnSuccess(true); err != nil {
    pterm.Warning.Printf("cleanup issue: %v\n", err)
}
```

Errors from failed restores are joined via `errors.Join` and returned to the caller so file-restoration failures are never silently swallowed. Backup files are only deleted physically once their corresponding restore succeeds, preserving the last-known-good copy on failure.
