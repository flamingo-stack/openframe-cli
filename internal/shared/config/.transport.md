Configures Kubernetes REST client TLS settings for local development clusters, selectively disabling certificate verification only when the API server is running on a local/loopback address.

## Key Components

| Symbol | Description |
|--------|-------------|
| `ApplyInsecureTLSConfig` | Mutates a `rest.Config` to skip TLS verification for local clusters while preserving client certificate auth |
| `isLocalAPIServer` | Determines whether a server URL resolves to a local address (loopback, `localhost`, `0.0.0.0`, `host.docker.internal`, `::1`) |
| `ApplyInsecureTransport` | Deprecated alias for `ApplyInsecureTLSConfig` |

## Usage Example

```go
cfg, err := clientcmd.BuildConfigFromFlags("", kubeconfig)
if err != nil {
    log.Fatal(err)
}

// Skips TLS verification only if the server is local (k3d/kind/WSL2).
// Remote/production clusters are left untouched.
cfg = config.ApplyInsecureTLSConfig(cfg)

client, err := kubernetes.NewForConfig(cfg)
```

## Behavior Notes

- **Local detection only**: TLS bypass is applied exclusively when `Host` resolves to a loopback IP, `localhost`, `0.0.0.0`, or `host.docker.internal`. All other hosts — including `.local` mDNS names — are treated as remote and left unchanged.
- **Preserves client auth**: `TLSClientConfig.CertData`, `KeyData`, `CertFile`, and `KeyFile` are intentionally kept intact so mutual TLS authentication still works against the local server.
- **Clears conflicting fields**: `CAData`, `CAFile`, `Transport`, and `WrapTransport` are cleared to prevent conflicts with client-go's internal transport builder.

> **Warning:** Never use `ApplyInsecureTLSConfig` against production clusters. It disables server certificate verification entirely for matched hosts.
