## status_theme.go

Configures the visual theme of pterm's package-level status printers (`Info`, `Warning`, `Error`, `Success`, `Debug`) used throughout the CLI, adapting output style based on terminal interactivity and CI context.

## Key Components

- **`ApplyStatusPrefixTheme()`** — Restyles pterm's global status printers. In interactive terminals, uses minimal glyph prefixes from the shared `GlyphSet` (bullet, `▲`/`✖`/`✔`), which auto-degrades to ASCII when needed. In non-interactive contexts (CI, pipes, `--plain`), uses lowercase, column-aligned word tags (`info`, `warning`, `error`, `success`) with foreground colors instead of block badges. Must be called once, early, from `ApplyGlobalOutputFlags`, after `--plain`/`--silent` flags are applied.
- **`annotationWriter`** — An `io.Writer` that tees printer output into GitHub Actions `::warning::`/`::error::` workflow commands, stripping ANSI codes and the printer's own prefix tag. Deduplicates identical messages per process to avoid flooding GitHub's 10-annotation-per-step limit (useful for repeating log messages like polling loops).
- **`newAnnotationWriter(inner io.Writer, level string) io.Writer`** — Constructs an `annotationWriter`, defaulting to `os.Stdout` if `inner` is nil.

## Usage Example

```go
package main

import "github.com/flamingo-stack/openframe-cli/internal/ui"

func main() {
    // Apply flag-derived output mode first (--plain/--silent/--verbose),
    // then theme the shared status printers.
    ui.ApplyGlobalOutputFlags()
    ui.ApplyStatusPrefixTheme()

    // From here on, calls anywhere in the CLI use the themed style.
    pterm.Info.Println("Cluster provisioning started")
    pterm.Warning.Println("ArgoCD app stuck in Progressing state")
}
```

**Behavior notes:**
- Inside GitHub Actions (when `InGitHubActions()` is true) and not silenced, `Warning` output is teed into `::warning::` annotations for PR/job visibility.
- `Error` annotations are handled separately by the shared error handler (not wired here) to avoid duplicate annotations.
- Interactive `Info` uses gray; non-interactive `Info` uses cyan since the tag becomes the only severity signal in colorless logs.
