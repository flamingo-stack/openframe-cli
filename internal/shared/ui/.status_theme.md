## status_theme.go

Configures the visual style of pterm's package-level status printers (`Info`, `Warning`, `Error`, `Success`, `Debug`) so the entire CLI has consistent, context-aware output theming — quiet glyphs for interactive terminals, and aligned lowercase word tags for CI/plain/piped output. It also bridges Warning output into GitHub Actions annotations.

## Key Components

- **`ApplyStatusPrefixTheme()`** — Restyles pterm's global status printers. In interactive terminals, uses glyphs from the shared `GlyphSet` (bullet, ▲, ✖, ✔, degrading to ASCII when needed). In non-interactive contexts (CI, pipes, `--plain`), uses lowercase, column-aligned, color-coded word prefixes (`info`, `warning`, `error`, `success`, `debug`) instead of pterm's default block badges. Must be called once, early, from `ApplyGlobalOutputFlags`, after `--plain`/`--silent` are applied.
- **`annotationWriter`** — An `io.Writer` wrapper that tees printer output into GitHub Actions `::warning::`/`::error::` workflow commands, stripping ANSI codes and the printer's own prefix, and deduplicating repeated messages per process (to avoid flooding the log or exceeding GitHub's 10-annotations-per-step limit).
- **`newAnnotationWriter(inner io.Writer, level string) io.Writer`** — Constructs an `annotationWriter` for a given severity level (`"warning"` or `"error"`), falling back to `os.Stdout` if `inner` is nil.
- **`ansiSeq`** — Package-level regexp used to strip ANSI escape sequences from captured printer output before annotation.

## Usage Example

```go
func ApplyGlobalOutputFlags() {
    // ... apply --plain / --silent flags first ...

    // Re-theme pterm's global printers based on terminal mode and CI context.
    ApplyStatusPrefixTheme()
}
```

Once applied, all existing call sites automatically use the new theme:

```go
pterm.Info.Println("Cluster provisioning started")
pterm.Warning.Println("ArgoCD app stuck in Progressing state")
pterm.Error.Println("Failed to connect to cluster")
```

Note: only `Warning` is teed into `::warning::` annotations (when running inside GitHub Actions and not silenced); `Error` annotations are handled separately by the shared error handler to avoid duplication.
