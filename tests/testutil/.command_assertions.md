Provides structured assertion helpers for verifying CLI command construction security properties against a `MockCommandExecutor` log, without executing any real binaries.

## Key Components

### Assertion Functions

| Function | Audit Guard | Purpose |
|---|---|---|
| `AssertNoArgContains` | I1 | Ensures a secret/token never appears in any argv element or command name |
| `AssertNoBashCConcatenation` | I3 | Detects injected arguments reaching a `bash -c` / `sh -c` shell string |
| `AssertArgIsDiscrete` | I3 | Verifies an argument was passed as a standalone argv element, not spliced into a shell string |
| `AssertNoDeleteOf` | I7 | Guards against destructive commands targeting protected resources (e.g. `kube-system`) |
| `AssertNoCurlPipeShell` | I5/M1 | Detects `curl ... \| bash` remote-download-pipe-to-shell patterns |

### Helpers

- **`HasShellMetachars(s string) bool`** — Exported utility; reports whether a string contains shell-dangerous characters (`$(`, `` ` ``, `&&`, `||`, `;`, `|`, `>`, `<`, `\n`)
- **`shellCScript`** — Extracts the script body from `bash -c`/`sh -c` invocations, including WSL-wrapped variants
- **`isShell`**, **`containsArg`**, **`render`** — Internal helpers for command inspection and test output

## Usage Example

```go
func TestHelmInstall_CredentialSafety(t *testing.T) {
    mock := executor.NewMockCommandExecutor()
    // ... run CLI code under test using mock ...

    cmds := mock.RecordedCommands()

    // I1: token must never appear in argv
    testutil.AssertNoArgContains(t, cmds, "ghp_secrettoken123")

    // I3: release name passed verbatim, not concatenated into a shell string
    testutil.AssertArgIsDiscrete(t, cmds, "my-release")

    // I3: no argument-derived metacharacters reaching bash -c
    testutil.AssertNoBashCConcatenation(t, cmds, "my-release")

    // I7: kube-system must not be deleted
    testutil.AssertNoDeleteOf(t, cmds, "kube-system")

    // I5/M1: no curl|bash patterns
    testutil.AssertNoCurlPipeShell(t, cmds)
}
```

> **Why discrete argv matters:** Because the mock preserves argv as individual elements, these assertions can distinguish `exec("bash", "-c", "helm install "+userInput)` (dangerous) from `exec("helm", "install", userInput)` (safe) — a distinction a flattened string log cannot make.
